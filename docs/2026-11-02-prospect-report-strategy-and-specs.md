## 1. 准确性立场

**系统无法保证结果绝对客观、不出错**，任何本地 SEO 工具都做不到。对外不宣称“100% 准确”。

出错来源：

| 层面 | 原因 | 能否消除 |
|---|---|---|
| 数据源 | 搜索结果随位置、时间、设备变化；SerpAPI 只是一次采样；公开 GBP 有延迟、字段不全 | 不能。只能记录采样条件 |
| 抓取 | JS 渲染、轮播、懒加载、反爬 | 只能降低；“未检测到”与“不存在”必须分开 |
| 解析识别 | 地址、实体、链接归属可能识别错 | 只能降低；靠金标准样本和否决数据迭代 |
| 判断 | 类别是否匹配、优先级排序属于专业判断 | 不能。最终判断交给 SEO |
| 因果 | 排名算法不公开，“为什么他们排在前面”只能是推断 | 不能。明确标为推断并列出依据 |

产品承诺：

1. **事实可追溯**：每个事实附抓取时间、采样条件、原始值、截图。
2. **事实 / 推断 / 建议分层标记**。
3. **“未检测到”不写成“缺失”**；没有数据的模块写“未评估”。
4. **LLM 不产生事实**：只负责把结构化证据写成文字；文中数字和实体必须与证据逐一校验，对不上不发布。
5. **可复现**：同一证据快照，结论相同。
6. **错误率可测量**：SEO 否决率 + 金标准样本集；阶段 0 结束时给出第一版基线。

对外表述：“证据可追溯的专业初稿，由你确认后署名。”

## 2. 获客周期

```
① 选目标 → ② 初筛 → ③ 深度诊断 → ④ 专业审核与编辑 → ⑤ 外联触达 → ⑥ 通话与提案 → ⑦ 签约衔接
```

| 环节 | 我们提供 | 优先级 |
|---|---|---|
| ① 选目标 | 行业 + 城市 → 按机会大小排序的潜在客户清单 | P2 |
| ② 初筛 | 免费快照：Map Pack 位置、GBP 与前三名基本差距、是否可索引；输出“机会大 / 中 / 小” | P1 |
| ③ 深度诊断 | 报告模块 A–E（见第 3 节） | P0 |
| ④ 审核编辑 | 逐条确认 / 否决 / 改写 / 隐藏 / 新增、截图标注、发送前检查、白标（见第 4 节） | P0 |
| ⑤ 外联 | 一页摘要 + 完整报告两种形态；外联文案生成。**不做打开追踪** | P1 |
| ⑥ 提案 | 通话要点、发现 → 服务范围映射、提案草稿 | P2 |
| ⑦ 衔接 | 获客报告作为基线 → 接入 GSC/GA4 → Verified Action Plan → 前后复审 | P1（主要是打通入口） |

衡量指标：

| 环节 | 指标 |
|---|---|
| ② | 快照 → 完整报告转化率 |
| ③ | 生成耗时；每份发现数 |
| ④ | **否决率（目标 < 15%）**；平均修改条数；审核耗时 |
| ⑤⑥ | SEO 自报：回复 / 通话 / 签约数 |
| ⑦ | 获客报告转入服务的比例 |

## 3. 规格一：报告模块 A–E

### 3.0 通用发现外壳

在现有 finding（`observed_fact`、`interpretation`、`judgment`、`confidence`、`limitations`、`evidence_ids`、`comparison_scope`）基础上新增：

| 字段 | 取值 | 说明 |
|---|---|---|
| `kind` | fact / inference / recommendation | 现有 `classification` 只有 `fact`，需扩展 |
| `status` | confirmed / not_detected / not_checked / not_assessed | 仅对 fact 生效 |
| `confidence` | high / medium / low | 仅对 inference 生效（现有字段保留） |
| `coverage` | 已查 ✓ / 未查 ✕ 的来源列表 | 例如“网站 ✓、GBP ✓、citation ✕” |
| `client_text` / `advisor_text` | 两套文字 | 坐标、语言、设备等内部参数**只能出现在顾问版** |
| `vertical_rule` | 规则包 ID 或 generic | — |

状态映射：

| 现有状态 | 呈现 |
|---|---|
| GBP `observed` | 已确认 |
| GBP `returned_empty` | 未检测到（“公开数据中未返回该项”） |
| GBP `not_returned` / `unsupported` | 未检查（“该数据源不提供此项”） |
| GBP `request_failed` | 未检查（“本次采集失败”），顾问版提示重跑 |
| 对齐 `site_missing` | **页面未检测到**（不是“页面没有”） |
| 对齐 `not_checked` | 未检查 |

硬规则：只有 `confirmed` 的事实能作为推断和建议的依据，也才能进入客户版。`not_detected` 可以在客户版出现，但只能用中性措辞（“我们在页面上没有找到 X，建议确认”）。

### 3.A 现状（排名可见度）

| 字段 | 层 | 来源 | 无数据时 |
|---|---|---|---|
| 目标词（3–5 个） | 输入 | SEO 填写，系统建议 | — |
| 每词 Map Pack 名次 | fact | SerpAPI Maps | “采样中未出现在前 20”，不写“没有排名” |
| 每词自然排名 | fact | SerpAPI | 同上 |
| 采样条件 | fact（顾问版） | 采集记录 | — |
| 排在前面的商家 | fact | 同一样本 | — |
| 可见度强 / 中 / 弱 | inference | 多词多点位综合 | 少于 2 个词有数据时“未评估” |

### 3.B GBP 与页面体检

| 字段 | 层 | 说明 |
|---|---|---|
| 主 / 次类别 | fact | 次类别公开数据常不全，拿不到标“未检查” |
| 服务项、营业时间、照片数、帖子 | fact | 帖子只作辅助项，权重调低 |
| 评论数、评分、最近评论日期、未回复数 | fact | — |
| **经营模式**（门店 / 上门服务区 / 混合 / 集合点） | inference → SEO 确认 | **地址对齐判断之前必须先确定** |
| GBP × 页面 NAP 对齐 | fact | 页面端抽取失败一律“页面未检测到”，**不得判为 mismatch** |
| 类别 × 页面意图 | inference | 语义判断（“tour operator” 与 “volcano tours” 判一致） |
| schema × 页面 × GBP 三方比对 | fact | — |
| **信任声明校验** | fact | 页面徽章 / 评分链接是否指向本商家自己的实体 |

### 3.C 页面漏洞

| 字段 | 层 | 说明 |
|---|---|---|
| 技术门槛：HTTP 状态、noindex、canonical、robots | fact | **不通过时其他页面建议全部降级**，排第一 |
| 移动端、点击拨号 | fact | — |
| 已检查页面清单 | fact（顾问版） | — |
| 本地实体：覆盖 + 位置（标题 / H1 / 正文 / 页脚） | fact | “有 / 位置偏弱 / 未检测到”，不写“未找到本地内容” |
| 运营证据 | fact + inference | 走行业规则包；站内其他页面已有证据时，建议“引用已有证据”而非“新写” |
| 评价展示：检测到几条、解析成功几条 | fact | 轮播解析不全时标“评价覆盖可能不完整” |
| CTA 与转化路径 | fact + inference | — |

### 3.D 竞品差距

沿用 `competitor_findings.py` 的三条约束：至少 2 个竞品有而客户没有才判为差距；采集时间差超过 24 小时不比较；样本不足标“未检查”。

| 字段 | 层 | 说明 |
|---|---|---|
| 竞品名单（前 3–5） | fact | 来自模块 A 同一样本，SEO 可删改 |
| 类别对比 | fact | — |
| 评论对比：数量、评分、近 90 天新增、最近日期 | fact | — |
| 照片数、服务项数 | fact | 需实测 SerpAPI 是否可得 |
| 落地页对比：页面数、本地实体数、案例 / 资质 / 价格 | fact | — |
| **为什么他们排在你前面** | inference | 只能基于已确认差距；每条写依据；客户版用“很可能是原因之一” |
| 数据缺口说明 | fact | 外链、citation 本阶段不查，明确列为“未纳入” |

### 3.E 机会与建议

每条固定结构（来自 PDF 反馈 3.15）：问题 → 依据（≥1 个已确认事实 ID）→ 为什么重要 → 具体修法 → 改在哪里（本页 / 其他页 + 内链 / GBP 后台）→ 示例文案（内容类必填，生成后校验实体和数字）→ 优先级 / 工作量 → 置信度 → 修完怎么验证。

客户版 1–5 条。

### 3.F 行业规则包

| 维度 | 家居维修 | 牙科 | 律所 |
|---|---|---|---|
| 典型经营模式 | 上门服务区 | 门店 | 门店，部分上门 |
| 运营证据 | 检修 / 安装案例、社区、前后对比照片 | 医生资质、具体项目、设备 | 执业资格、案例结果、执业领域 |
| 关键信任信号 | 执照号、保险、保修、24 小时 | 执业医师、可用保险、预约 | 州执业资格、免费咨询、风险提示 |
| 合规敏感点 | 低 | YMYL：不对疗效下结论 | YMYL + 各州律师广告规则：规避“专家”“保证胜诉” |
| 页面结构重点 | 服务 × 城市页 | 项目页、医生页 | 执业领域页、律师页 |
| 重点 GBP 字段 | 服务区、服务项 | 预约链接、属性 | 细分类别 |

其他行业走通用规则，报告标注“未启用行业专属规则”。

## 4. 规格二：审核编辑

### 4.1 流程

```
初稿（待审核）→ SEO 逐条处理 → 发送前检查（提示不拦截）→ 冻结为交付版 v1 → 可继续修改为 v2，旧版保留
```

### 4.2 逐条操作

| 操作 | 效果 | 必填 |
|---|---|---|
| 确认 | 原样进客户版 | — |
| 否决 | 不进客户版 | 原因（见下） |
| 改写 | SEO 文字替换客户版文字，原文进修改记录 | — |
| 隐藏 | 结论成立但不给客户看；**不计入误报** | — |
| 新增 | SEO 自加条目，可上传截图；无系统证据时标“顾问判断” | — |
| 排序 / 改优先级 | — | — |

否决原因（固定选项）：

1. 事实错误（系统没抓到） → 计入误报率
2. 判断错误（事实对，结论不对） → 计入误报率
3. 不适用于该行业 / 经营模式 → 计入行业规则缺口
4. 不重要 / 优先级错误 → 计入优先级模型问题
5. 重复
6. 其他（填说明）

### 4.3 发送前检查（全部为提示）

- 有未审核条目（默认不进客户版，可一键全部确认）
- 有低置信度推断进了客户版
- 客户版条目引用了“未检测到”的事实
- 改写文字中的数字与证据不符
- SEO 改写文字命中客户版安全过滤（网址、内部 ID、效果承诺、坐标）
- 白标信息未填

### 4.4 修改记录

```
ReviewItem（按版本追加，不覆盖）
  item_id, source(system|advisor), action(confirm|reject|rewrite|hide|add|reorder),
  reject_reason(1–6), note, original_text, advisor_text,
  evidence_ids(可为空), attachments, order, recorded_at
```

只在顾问侧可见。已冻结证据永不修改，SEO 的修改永远是叠加层。

## 5. 与现有代码的差距（2026-11-02 核查）

| 位置 | 现状 | 需要的改动 |
|---|---|---|
| `SearchTrust-RD/app/report_v22/site_business_html.py` | 电话只认 `tel:` 链接；地址只认 `<address>` 或“标签 + 值”结构；不渲染 JS | 补充文本电话号码识别、与 GBP 地址模糊比对（结果标为 inference）；关键页渲染兜底 |
