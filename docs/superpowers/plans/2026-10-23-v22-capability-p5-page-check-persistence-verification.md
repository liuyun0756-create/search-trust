# P5 页面检查授权、保存与恢复：验收记录

日期：2026-10-23。依据：[已批准设计](../specs/2026-10-23-p5-page-check-persistence-design.md)、[实施清单](./2026-10-23-p5-page-check-persistence-implementation.md)。

## 本批交付

页面检查接通数据库中的完成 Verified 报告、指定批准交付、实施修订、行动和确认业务范围。创建、领取及保存时均核对当前来源；实施修订按同一交付的最新版本判断，不只按记录根 ID 判断。Case 版本、业务范围或实施修订变化阻断待完成检查；新的草稿不抹掉既有批准版本。

新增独立任务与不可变观察表。每个 Case 最多一项待处理/运行中任务；queued 10 分钟过期，执行租期 2 分钟，单次领取。结果与完成状态同事务保存，并由延迟约束校验一致性。Case → 报告 → 任务的锁顺序与实施记录保存的报告锁协调。

同请求返回原记录；保存响应丢失可读取原结果或重发相同完整观察，不能重抓网站。取消/领取响应丢失保留租期，到期由显式内部事务结束；没有自动重试或后台过期任务注册。只读详情及最多 20 条历史摘要不改变状态、不续租、不联网。

任务完成与检查成功分离：checked 与完整的 unable_to_check 均可保存为 completed。内部异常、中断和来源过期只产生 failed，不产生“未观察到修改”的伪结果。结果仍不证明渲染、功能、实施全部完成或 SEO 效果。

## 修正与边界

首轮隔离验证修正了 SQL 条件语法及延迟一致性触发器的执行身份；触发器使用受限定义者权限，不通过放宽表权限解决。原生测试中的 Case 归档/批准状态准备也遵守既有约束。

匿名和登录角色不获得新表访问权；服务角色不能直接写新表，也不能执行内部辅助函数。仅私有事务入口可操作。源读取上限 2 MiB，任务响应 128 KiB，选择 20 KiB，计划/观察分别 64 KiB；不保存页面全文、令牌或异常原文。

本批没有新公开按钮、路由、派发或清理任务；没有实际开关、正式数据库、部署或收费规则变化。没有 UI 改动，未重跑前端构建或浏览器，不把旧浏览器结果计入本批。

D1 保持：正常完成但不足以提出行动，仍交付诊断、消耗 1 点、不返还；原技术失败规则不变。本批不新增扣点，也不承诺未来页面检查免费无限量。

下一步是显式确认、状态/历史与受控派发入口；开放前仍需明确频次和成本边界。GA4 实际可比资格、真实校准、附件、新版收费复核和正式发布验收仍待推进。**P5/P6 和总计划未关闭。**
