生成报告正文、报告校验值、已保存批准/分享及客户/PDF 投影保持原有规则。差异是独立生成版本快照，不能伪装成下方交付编辑器的实时比较。历史无快照时显示未记录，存储错误显示不可核实；均不写成零变化。

## 具体设计与权限

`capability_review_report_differences` 只保存前后各最多三项事实/计划和固定引用，不嵌套前轮完整输入。5 MB 总上限覆盖已有报告/输入边界；不扩展来源采集预算。快照含自身摘要，数据库列另校验完整 payload 摘要。

`complete_v22_review_analysis` 保留原锁、代次/期限、一次消费和成功恢复逻辑，在同一事务追加派生快照。原函数改为内部实现并撤销普通执行权限。读取 RPC 从当前已完成报告/冻结输入和原已完成来源重新核对固定内容；原任务终态重放不会替没有快照的老报告补写历史。普通角色不能直接读取/修改/删除表，也不能提交任意差异。

默认关闭 `V22_REVIEW_DIFFERENCES_ENABLED`，还依赖现有 capability/delivery 门槛。只控制 SEO 展示；暂停新收费任务不影响免费读取。新 metadata 不进入客户出口，不增加单独分析或强制编辑要求。

## 具体问题与处理

| 问题 | 处理与证据 |
| --- | --- |
| 原差异函数要求完全相同的源计划，不能直接当跨轮报告比较 | 新独立规则固定上一份已批准计划，证据单独按目标和 ID 对齐；旧函数/旧契约不重解释 |
| Pydantic 严格模型的测试错误使用 Python 字典构造 UUID | 改用实际存储的 JSON 解码入口；未放宽模型或来源校验 |
| 测试篡改快照时先更新 payload 被摘要约束直接拒绝 | 测试改为同语句重签内外摘要，读取仍拒绝，证明不是只依赖自签 hash |
| 测试账户已存在首份服务扣点，不能硬编码从五点开始 | 零行动原生测试以真实起始余额为准，验证两次生成恰好消费两点，免费记录不扣点 |
| 完整报告和获准长文案可能合法超过 3 MB 派生数据 | 差异总边界改为有输入上限依据的 5 MB，仍有界且不递归；最终原生专项复验 |
