# P5-02 授权比较读取与不可变保存：本地验收

依据已确认 P5 总计划继续实施。设计：`../specs/2026-10-22-p5-comparison-storage-design.md`。本批完成内部读取、计算、固定保存和恢复链路；没有公开 HTTP/UI 入口，不将 P5-02 或 P5 整体标为完成。

## 实现与边界

- 新增第 61 个增量迁移 `20261022120000_freeze_v22_comparison.sql`，仅在本地隔离数据库应用。`capability_comparisons` 保存原始规范化请求、结果、两个摘要、精确实施修订、来源引用及保存时点；更新/删除触发器拒绝变更，服务角色也没有直接写权限。
- 专用读取函数只接受所有者、Case、精确实施引用、行动、窗口长度、范围及来源 ID 等选择信息。实施记录来自数据库，沿用已完成并消费的 Verified 与已批准交付版本资格校验。不会从请求接受替代的实施记录或来源数据。
- 每个来源检查 Case/绑定/所有者、已确认身份、当前连接状态与对应只读权限、资源 ID、规范化模式、覆盖范围和健康元数据。历史基线允许自然到期；当前观察必须未到期，且是绑定上的最新快照。实际来源摘要和健康原因由已有后端校验器重新验证。
- 来源内容有效但业务数据不足可以进入比较，保留 `insufficient / SOURCE_UNHEALTHY`；未采集的维度保留 `not_comparable`。缺少来源时记录等待或不足，不借用别的 Case，不补零。非法来源与权限拒绝属于错误，不伪装成“无效果”。
- 保存事务重新读取并核对全部输入，防止计算后断开权限、替换资源或出现更新来源。连接、Case、绑定按既有同步锁顺序锁定，再保护来源；比较 UUID 的事务锁串行化相同保存，不反转同步的锁顺序。
- 同一个比较 UUID 和同一选择重试返回第一份固定结果，保留原评价时点；同 ID 不同选择冲突。新的数据检查应使用新 ID。调用端必须在响应不确定时保留原 ID。实施日期修订不更新旧比较。
- SQL 绑定输入、记录、来源、范围、规则和结果摘要；内部 Python 仓储在每次读回时完整重算并核对结果。只重新签名却篡改了数字或窗口的响应仍会被拒绝。计算职责留在服务端，SQL 不重复实现指标算法。
- 历史比较读取继续检查所有者及原报告交付资格，但不要求 OAuth 仍有效。撤销数据权限阻止新比较，已有比较仍能按原时点回放。不会用今天的时效条件改写旧结果。
- 原生数据库暴露出非 UTC 会话时区问题：来源采集时间可能带 `+08:00`。修正结果引用统一转换为 UTC Z；没有改变实际时间、窗口或数值。新增回归测试，旧契约样例仍逐字一致。

全部调用均为免费内部存储动作，不创建分析任务，不修改余额、账本、原报告、批准修订、PDF 或分享。来源为已有 GSC/GA4 快照，没有供应商采集调用。效果资格仍为 `pending_metric_specific_calibration`、效果结论为空、因果归因为 false。GA4 比较限制保持原状，未开放效果解释。

新增原生测试从实际首次服务生成和结算开始，保存批准交付、实施记录，再由实际比较仓储通过本地传输访问原生 SQL。只有来源和 HTTP 运输受控，不依赖模拟 SQL 权限。覆盖：

1. 六个并发同选择请求只保存一份，旧基线到期仍可用；修正日期及移除授权后原比较保持相同。
2. 错误所有者、Case、行动、实施修订和来源 ID 被拒绝；读取后连接失效、身份待确认或新增快照均阻止保存。
3. 篡改输入、因果/效果输出和摘要被拒绝；保存响应丢失后从数据库恢复同一份缺数据结果。
4. 同 ID 三种窗口竞争只允许一种胜出；匿名/登录浏览器角色不能调用 RPC；服务角色不能调用内部来源辅助函数或直接写表；到期当前快照不能开启新比较。
5. 不支持的维度和有效但数据不足的来源均保留状态及原因，差值为空，不生成效果结论。

每个场景检查报告、任务、余额和账本与比较前完全一致。原有一次扣点、正常零行动不返还、技术失败一次补偿测试也继续通过。本批没有 React/页面改动，因此未重复页面构建和视觉截图，未把上批浏览器结果算作本批新验证。
