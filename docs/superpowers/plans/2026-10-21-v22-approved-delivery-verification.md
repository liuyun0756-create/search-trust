# P2 接续：批准版本 PDF 与客户分享

日期：2026-10-21。本轮属于既有 P2 交付出口接续，不代表 P2 全阶段或生产完成。

## 输入、输出与边界

- 输入仅为已完成、已结算报告及已保存的批准修订。所有者通过当前修订号请求新交付；草稿、旧页面修订和跨用户报告拒绝交付。
- 所有者 PDF、客户网页及客户 PDF 共用同一批准投影。下载只读取，不重新分析、不改写原始证据、不收费。
- 新分享独立存储，绑定 report/revision ID，数据库只保存 256 位随机令牌的 SHA-256。有效期 30 天，同一报告最多 20 个有效链接。
- 创建分享与保存修订使用相同报告行锁；创建时再次检查最新批准修订，阻止校验后被新草稿取代。旧分享不自动轮换，不跟随新草稿或新批准内容；必须主动撤销或到期才失效。
- 撤销幂等且不可撤回；每次打开和下载重新检查有效性。已经下载的 PDF、已经展示的内容无法远程收回。
- 令牌在 URL fragment，解析/下载通过有大小限制的 POST JSON 传输，页面和响应禁止缓存、索引与 referrer；客户页无编辑控件或分析追踪。
- 白标字段沿用现有产品边界：本次 PDF 下载可带姓名/企业名、客户名称、页脚、PNG/JPEG Logo；不保存为全局品牌，不改变线上分享，保留 SearchTrust 标识。

## 代码与迁移

- 新迁移 `20261021150000_share_v22_approved_capability_reports.sql`：独立 share 表、不可变守卫、owner/list/revoke/resolve RPC。表启用 RLS，所有应用角色无直接表权限；只有 service_role 可执行指定 RPC。
- 新 owner `client-pdf` / `client-shares` 接口挂接报告页；客户端防重复请求，过期版本返回冲突，下载失败不伪装成功，复制失败允许手动复制。
- 公共 `/api/share/resolve`、`/api/share/pdf` 按版本分流；旧 resolver 成功不改变响应，只有明确 not-found 才尝试新链路，不能吞掉旧库异常。新链路仍需默认关闭开关。
- 新版 PDF 使用随应用打包的静态 Noto Sans SC Regular/Bold，许可证及来源摘要在 `public/fonts/capability/README.md`。缺失字形返回可解释错误，不静默丢字；不是全 Unicode/emoji 支持承诺。
- 字体生成必须带 `--update-name-table`，保留不同 PostScript 名称。初次检查发现同名字体导致正文误用粗体且复制文本缺少部分拉丁字母，修正名称后重新生成并检查。
- PDF 技能要求的渲染检查发现一个只剩背景/页脚的空白续页；修正可跨页证据卡底部留白，重新检查全部页。没有删报告内容来通过检查。
