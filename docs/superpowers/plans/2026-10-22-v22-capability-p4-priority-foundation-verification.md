## 2. 调查结论与设计

- 现状是：旧选择器主要按严重程度和置信度排序，服务选择器还根据材料标题识别技术前置；报告没有完整优先级轨迹。
- 关键约束是：不能改变已冻结任务的解释、旧报告摘要、批准修订和一次收费边界。
- 原先不明确但已确认的是：业务重点字段存在，但获客和首次服务创建范围时仍写入 `priority: null` / `target_pages: []`；材料类型 `measurement_check` 也包含联系路径调查，不能一概当成测量错误。
- 基于以上，先建立版本化、可回放的排序及阅读基础，再接业务重点输入和受约束调序。不改历史任务、不冒充已完成用户入口。

### 分层规则

先从有证据支持的候选行动构造依赖图。仅在依赖均已排在前面的候选中比较：

| 顺序 | 比较依据 | 边界 |
| --- | --- | --- |
| 1 | 访问/索引 → 测量可靠性 → 普通工作 | 使用规则身份，不依靠可编辑标题；联系路径调查不自动成为测量错误 |
| 2 | 确认目标页面 → 确认业务目标 → 无直接匹配/未知 | 不把没有匹配视为低价值；不从自由文本猜目标 |
| 3 | 支持 → 待核实 → 冲突 | 冲突仍保留观察，不能写成 SEO 原因或效果承诺 |
| 4 | 问题严重程度、证据置信度 | 是问题/证据属性，不是营收评分 |
| 5 | 可审阅材料 → 检查指令 → 待业务确认 | 不等于已执行或已发布 |
| 6 | 稳定行动 ID | 平级时确定性打破，枚举顺序不影响结果 |

影响路径和比较范围来自行动所关联的原始发现；具体目标页面匹配参与排序，不用跨范围流量大小猜业务价值。有限候选集沿用现有预算；超过三项的候选保留审计，不为它们伪造交付材料或名次。

业务目标首版只识别明确代码：`service_visibility`、`contact_path`、`business_identity`。其它历史文字原样保留，视为没有可识别的结构化目标，不做自然语言分类。目标页面只做同业务域名、准确路径与查询字符串匹配，统一默认端口、忽略片段，不根据子串匹配、竞品页面或猜测别名加权。

所有排序都明确：业务回报未知；GSC 点击、GA4 会话/配置事件不等于合格线索、营收或因果关系。
