## 1. 本批完成

### 用户可选设置

获客 coverage/开始报告环节和首次服务入口新增同一个表单：

- 已确认业务重点：服务可见性、联系路径、公开业务身份，或尚未确认。
- 已确认目标页面：最多 20 个同业务网站的完整 URL，可留空。不从竞品网站、子串或未检查页面制造建议。
- 独立 SEO 自己的执行容量：未安排、时间有限、可安排。
- 独立 SEO 自己的发布权限：未确认、需客户批准、可发布已约定变更。

没有另一位“执行者”选项，不要求填写工时、收入或预期 ROI。未知不等于低价值，也不假定无法执行。保持默认未知即可继续，填写不是额外的必填劳动。

保存免费，不创建分析、预留或消耗点数。保存状态与版本明确：未保存、加载失败或保存不确定时不能确认生成；失败保留输入；重新加载会明确替换未保存编辑。已提交的工作不会因之后的设置变化重新分析。

### 冻结点与并发

冻结点是“确认范围并准备诊断”，不是最初的竞品发现：

```text
保存可选设置（版本 N）
    → SEO 确认范围 / 竞品
    → 同一事务检查版本 N 并创建不可变 BusinessScope
    → 固定来源及输入清单 → 实际生成
    → 原始系统报告 → 交付修订 → 明确批准 → 固定版本 PDF / 分享
```

设置使用不可变历史版本和 Case 级锁。另一页面已经修改时，旧版本不能静默开始分析。保存响应丢失允许恢复完全相同的下一版本；不能借此覆盖不同设置。分析已登记后，重试优先恢复既有任务，即使当前设置已改变，也不会重建范围或增加扣点。

首次服务保持原有“连接 → Case → 工作流”锁顺序；新增原生并发测试验证设置保存与确认同时发生，无死锁、无错误替换、只有一份业务范围/任务及原一次扣点。

### 可解释条件与调序

- 新生成规则：`v22_capability_public_v3` / `v22_capability_service_v3`；新排序轨迹：`v22_business_priority_v2`。
- 已确认时间有限只影响其它因素可比时的执行条件平级规则，不能挤掉访问、索引、测量、业务相关性或更强问题/证据依据。不声称检查需要多少小时。
- 需批准时，发布型工作保留确认条件；未知权限不写成已批准或被阻断。
- “联系路径”可以匹配实际 GA4 联系路径调查规则；不会把所有测量工作误当作联系路径机会或测量错误。
- 新版交付可上移、下移和恢复系统顺序。明确行动依赖和访问/索引、测量可靠性、其它工作的前后层级在页面、TypeScript、Python、SQL 插入中一致保护。
- 恢复只改顺序，保留修改过的标题、步骤和材料；调序清除本次批准勾选。保存不扣点、不重新生成。
- 系统推荐保持不可变；交付阅读、PDF 和分享继续使用同一批准修订及投影。“为什么现在做”仍明确是原始系统理由，不为手动改稿编造新的证据解释。

## 2. 迁移、权限和兼容

新增本地迁移 `20261022100000_freeze_v22_planning_settings.sql`，总计 59 个迁移：

- 新增 `case_planning_settings` 不可变版本表及受授权的读取/保存 RPC。
- 获客和首次服务在创建新业务范围时附加已保存设置；旧范围、清单、报告及修订不更新。
- 两条带设置版本的确认包装函数将版本检查和冻结放入同一事务；已登记请求优先恢复。
- 新交付修订插入触发器保护前置层级与显式依赖；只对新轨迹 v2 应用，不追溯拒绝老已批准交付。
- `anon` / `authenticated` 无表或 RPC 访问权，服务端从当前登录用户取得 owner，不接受浏览器传来的 owner 身份。API 校验原点、正文大小、字段集合及同业务 URL。

BusinessScope 可选新增 `execution_conditions`；历史记录不添加 `null` 键，避免摘要变化。旧生成 v1、上一批生成 v2 / 排序轨迹 v1 均保留。四份既有实际生成报告摘要已固定回归；历史报告不按新业务条件重新解释。

新设置入口开关 `V22_PLANNING_SETTINGS_ENABLED` 默认关闭，还要求既有 `V22_CAPABILITY_DISPATCH_ENABLED` 为 true。获客 UI 另要求现有 capability intake 开关；首次服务 UI 继续遵守原准备/入口开关。**本批没有修改任何实际开关。**

关闭设置入口不是删除历史或降级已冻结 v3 任务；回退时应保留新旧读取和生成兼容，关闭新写入入口，不倒灌旧补丁或逆向覆盖数据库版本。

2. 确认时冻结联系路径重点、目标页、有限容量及需要批准的权限。
3. 确认后把当前重点改为业务身份，实际后端生成报告仍使用确认时的旧值。
