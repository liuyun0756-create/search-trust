## 完成内容

- 新增第 77 个迁移。固定选择按所有者读取，创建任务、扣减并预留 1 点、冻结完整输入、写入工作记录一起提交。任一步失败全部回滚。重复请求先查原任务，保留原输入/准备时间；同选择换 UUID 不会重复扣点。
- 只允许从当前已保存的 2.2.2 Verified 报告开始本轮生成；旧基准出现更新 Verified 时拒绝新任务。另有活动收费分析时拒绝并行开始。技术失败已补偿后允许另行确认新请求。
- 使用独立 SQL 工作表和 ARQ 函数，数据库掌握派发/执行租约、代次、截止和结算；浏览器和 Redis 不掌握点数。队列中断、响应丢失或执行进程退出后可恢复固定任务，旧代次无法完成新任务。
- 确定性内容生成消费固定来源与决定，不调用供应商、不重新采集、不让第三方模型代替 SEO 决定。复用正式报告完成事务，成功保存和消费原预留一起完成；没有下一步行动仍交付诊断且不返还。
- 技术失败/尝试耗尽/截止/归档只补偿未完成任务一次。提交成功但回执丢失时，SQL 优先恢复已保存报告，禁止补偿成功结果。
- 保存的决定版本上增加单独收费确认、状态、同请求恢复和完成后的审阅链接。编辑决定、保存交付和批准仍免费。刷新/另一设备可找回已有任务；未知开始结果保留同 UUID/正文，不自动创建替代分析。
- 内部 API 认证，BFF 同源校验与身份注入，严格字段/大小/重复键/响应校验；公开任务投影不含原始输入、私人理由和服务令牌。工作表启用 RLS 且禁止服务角色直写。
