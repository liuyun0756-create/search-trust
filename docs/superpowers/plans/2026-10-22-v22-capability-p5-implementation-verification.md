# P5-01：免费实施记录第一批验证

## 1. 本批结果

**只完成 P5-01 的记录主链，不宣告 P5 全部完成。** 已确认的总体方案为 2026-10-13 产品能力补齐计划，设计见 `../specs/2026-10-22-p5-implementation-record-design.md`。先调查已有代码：旧流程没有可直接复用的持久实施记录；capability manifest 虽定义 review/reference，SQL 和实际生成器仍不允许 review。

用户流程：完成 Verified → 原样或改稿后批准 → 在报告下选择已批准行动 → 核对预填范围 → 实施日期/时区 → 免费保存。备注、责任人可选；附件上传暂未实现。没有复杂任务板、自动抓取、周期任务或暗中开启的新分析。

三个状态分开：

- 实施：用户记录，保存修订号。
- 页面核实：本次记录未执行。
- 效果评估：尚未评估。

不把记录日期写成系统观察日期，不以行动完成标记宣称页面已改变或带来效果。

## 2. 版本和权限

第 60 个增量迁移 `20261022110000_record_v22_implementation.sql` 增加不可变 `capability_implementation_records` 及所有权读取/保存 RPC。只有已完成且已消费一次点数的 Verified 报告、持久批准修订能成为源。Prospect、候选报告、未完成/未结算任务、草稿和外部 owner/Case/report/revision 均不接受。

每份批准修订有独立记录根 ID 和修订序列，绑定原报告 checksum、批准修订 ID/序号。后续日期、范围、备注修正追加版本；取消勾选是新版本更正，不删除历史。界面显示最近 20 版，数据库完整保留；批准版本导航展示最近 100 个版本，已知更早批准 ID 的读取仍受同一所有权校验支持。新草稿出现不隐藏原批准版本记录，新报告不自动继承。

保存采取乐观版本比较与报告行锁。响应丢失只恢复紧邻的完全相同内容；不同内容冲突并保留本地输入，用户明确选择重新读取才丢弃本地修改。服务端写 recording timestamp，日期和 IANA 时区独立验证；后端可解析具体记录并形成已有 ImplementationReference，但未接通收费复核。

浏览器不提供 owner 身份。API 校验登录、原点、正文大小、字段集合及 UUID；仓储检查完成授权、批准源、返回身份/摘要与精确版本；SQL 独立保护同一范围和行动归属。表直接写入、更新/删除及客户端 RPC 权限关闭。实施范围仅作为文本保存，不用于请求任意 URL；附件/页面快照不在本批新增。

新 `V22_IMPLEMENTATION_RECORDS_ENABLED` 默认关闭，且要求 `V22_CAPABILITY_DISPATCH_ENABLED` 开启；关闭写入口不代表删除历史数据。本批未变更任何实际环境开关，未执行远程迁移、未提交、未部署。
