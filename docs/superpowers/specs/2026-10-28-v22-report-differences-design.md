# 正式复核报告版本差异

用户已批准补齐报告版本差异保存和展示，承接当前能力台账 Q15。按 brainstorming 核对现有上下文后采用以下设计，不再重复请求已授权步骤的确认。writing-plans 不在当前可用目录，沿用项目实施清单。保留全部未提交工作，不提交/部署/远程迁移或开启实际功能。

基线：`baseline-O3FYEh`，manifest SHA-256 `1c7d0176a11aac938ab573c7ae2b45b5c518ef9e27ab319354246efdc00576a0`。

## 选择与范围

运行时临时比较不能保证以后读取仍是相同基准；修改 2.2.3 报告正文/校验值会破坏旧报告和固定分享。采用独立、不可变的差异记录，与新报告完成及原一次消费在同一事务中保存。独立契约、规则号及摘要，不改变报告/批准/客户/PDF/分享内容或计费。

差异属于 SEO 所有者的审阅辅助，比较“本次系统生成的报告”与它实际复核的上一份已批准计划。它不是交付编辑器实时差异，也不把私人原因放入客户出口。页面明确这一点；已有报告没有记录时显示未记录，不回填伪造历史，不在 GET 中写入。

## 固定基准与语义

- 当前正式 2.2.3 报告绑定实际冻结输入；基准 report ID/完整摘要/版本、delivery ID/修订/摘要全部从该输入与已完成来源读取，不选当前最新计划。
- 下一步计划比较本次原始 actions 与冻结的已批准 actions，按行动 ID 对齐，显示新增、更新、未继续提出和原样保留，另记顺序改变。标题、目标、步骤、完成条件、复查方式和材料内容属于工作语义；材料来源 ID 不算文案改动。私人理由或相同内容的新版本号不制造建议变化。
- 证据比较本次 facts 和上一份 2.2.3 中同 ID、同目标、同业务范围的 facts。首次从 2.2.2 进入、行动没有旧观察时标首次依据；目标或业务范围不同标不可比。未选择某个来源展示为本次未选，不等于旧事实被推翻。
- 证据变化按实施记录、页面、GSC、GA4、核实条件分开。重新观察/生成时间、引用 ID 不算事实变化；窗口/资格/数值或实际页面检查结果变化可显示具体前后值，但不等于效果或因果。
- 快照最多保留前后各三项事实/计划，不嵌套完整历轮输入。零行动仍保留诊断；不自动补动作，不标已实施或改善。

## 存储与恢复

新增第 79 个兼容迁移和内部计算/读取函数。数据库只从可信已保存记录计算，调用者不能提交任意 diff。完成包装保留原锁顺序、执行代次、截止期限、结算和幂等校验；差异插入失败必须回滚报告/消费。精确重放恢复同一快照；老终态精确重放不补写历史。

表禁止普通角色直接访问和修改/删除。所有者读取检查 active Case、已完成当前报告、固定来源、记录摘要及重新计算结果；错误/缺失区分明确，不把存储故障显示成“没有变化”。前后端各自验证独立 schema、身份、绑定、摘要及变化标记，SQL/Python/TS 共享夹具回归。

## 页面

沿用现有绿色、深色文字和报告排版，增加紧凑的“Changes in generated version”区域。先展示明确的版本与批准修订基准，再分别展示证据、下一步工作。按行动展开实际前后内容；只对实际语义更新显示 changed 标记；首次依据、不可比、无变化使用中性状态。提供上一份所有者报告链接，保持历史交付修订的独立导航。

默认关闭 `V22_REVIEW_DIFFERENCES_ENABLED`，并依赖已有 review delivery 开关。关闭展示不影响已保存报告、原任务完成或差异持久化。无新付费操作、自动取数或新增客户分享字段。

## 验证

先以语义和原生事务/恢复红测验证缺口，再实现。覆盖重复来源时间/ID、仅指标变化、仅工作变化、相同行动顺序、材料引用重发、首次/不同目标/不同业务、来源未选、零行动、增删动作、私人原因不泄露、旧报告不变、越权/篡改/重放/插入失败回滚。类型/契约/普通与原生回归、实际所有者页面桌面/手机、键盘展开和生产构建检查后再记录完成。

自审：基准唯一且有界，展示与生成快照含义一致，无历史回写或因果推断；P5-02 校准、P6 真实验收与发布不在本项范围。
