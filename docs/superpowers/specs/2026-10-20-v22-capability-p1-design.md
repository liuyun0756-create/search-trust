# v2.2 P1：兼容契约与冻结输入

已依据主执行文档及 2026-10-20 D1 决策进入实现。

采用增量契约：保留现有 2.2.1 模型、生成与交付链；新增 2.2.2 能力契约，独立 schema、类型、固定样本和双端语义校验。新契约能表达获客、获客后服务、首次服务和复核；结论、证据、最多三项行动及限制各自有明确字段。零行动诊断正常交付，消耗一点；技术失败仍由现有失败工作流返还。

不采用直接放宽旧父报告/固定三项约束的方案：旧输入绑定同时承担所有权、来源资格、账本和恢复校验，局部放宽会跳过这些要求。也不在本阶段重写已经工作的生成器：P2/P3 将在新基础上接入生成和收费入口。

分析输入单独冻结：Case/用户、任务、模式、业务确认版本、快照引用及校验值、评价时点、规则版本和前一报告。首次服务没有前一报告，仍要求完整当前来源。获客只用公开来源；服务需要匹配健康且未过期的 GSC、GA4、公开 GBP；官方 GBP Performance 可选。复核另携实施记录版本，P5 接入真实实施外键及资格规则之前不开启复核任务。

数据库只新增业务版本与输入清单、逐快照引用和扩展交付修订。业务确认与抓取事实分别保存；快照/原始报告不可通过交付修订改写。冻结绑定已有任务和一次性账本记录，无额外扣点。精确重放返回原绑定；同任务更换来源或校验值报冲突。新冻结检查真实存储来源、所有权、身份、授权及时效；保存后的清单不跟随“最新快照”漂移。

交付修订有期望版本、草稿/批准状态、只允许修改叙事和已有行动。批准可以零修改；证据不进入编辑字段。新类型提供统一阅读投影和动态行动渲染，后续客户/PDF/分享接入同一批准版本。旧契约继续由旧校验器读取，不把旧报告填补成新格式。

验收：固定四种模式及 0/1/2/3 行动样本；跨 Case、失效/撤销、来源缺失、摘要篡改、伪历史差异、行动/证据孤立和修订并发拒绝。隔离 PGlite 跑增量迁移、RLS、冻结重放和余额不变；既有账本/任务失败恢复继续全量回归。新入口接入和真实付费运行属于后续阶段。
