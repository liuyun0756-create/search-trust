# 首次服务用户入口接线

接续已批准主计划 P3 和同点数续接方案。本批采用独立默认关闭入口，不复用会扣 Prospect 点数的旧发现入口，也不修改旧 Verified 父报告规则。

## 流程与实现

免费准备页面保留客户和来源信息。新增独立步骤区：范围/查询与费用确认 → 后台发现 → 选择 1–3 个竞品 → 原预留下生成首次服务报告。准备开关不等于收费开关；新增收费入口开关同时要求现有准备、能力派发开关。所有实际环境配置保持不变。

GET 只读取当前 owner Case 的最新工作流、当前发现、源快照元信息和余额，不触发收费或刷新。POST 使用严格动作白名单、认证 owner、同源校验、请求体大小限制和唯一操作键。开始需要明确 accepted_credit=true 与用户见到的范围指纹和源快照 ID。任何状态不明均保留原任务，先读回状态，不自动退款或自动重收费。

竞品结果只来自后台已保存记录；浏览器不能提供证据、摘要、成本、结果或退款理由。确认提交发现 ID 和候选 URL 选择，服务端建立规范化采集请求；SQL 原子保存业务确认、绑定原扣点、登记采集。核查发现已有准备执行器但缺少自动扫描接线，因此本批补充默认关闭的后台恢复扫描，读取已登记且未过期任务，再由现有 SQL 租约授权执行。保留原尝试、成本与截止时间；已冻结的输入只接续派发，不重新采集。已登记的相同确认可重放；不同选择和迟到页面冲突，不覆盖。

补充和刷新使用已有续接事务，提交预期当前发现和快照；共用原预算。最多三次总执行，达到上限明确暂停且不增加扣点；零候选不承诺报告能继续。账本丢失/过期沿用现有技术恢复规则。源过期或权限撤销提示回到数据连接同步，GET 的准备状态不替代事务内复核。

## 展示

沿用产品深绿/浅绿工作台样式，标题与步骤、范围和费率、单个当前状态面板。候选以带复选框的紧凑卡片显示业务名、网站、相关性说明；不伪造预估进度。付费明确点击，竞品确认写“使用已预留点数，无额外收费”。无自动轮播、无自动确认；错误为可读提示，网络失败时保留输入并显示检查当前状态按钮。

正常完成但没有行动依然交付诊断并消费 1 点；技术失败仅一次返还。失败后重新开始必须重新明确确认。公开发布仍需真实环境、原生并发、授权、供应商及预算阻断处置验收，本批不部署、不启用。

## 验证

全迁移 SQL 测试覆盖确认原子性/回滚、仅一次扣点、跨 owner、旧页面、响应丢失重放、不同选择冲突、来源变化、公开角色无权限。路由测试覆盖开关、认证、同源、体积、字段白名单；组件测试覆盖无自动收费、勾选同意、当前状态恢复、选择与异常。浏览器使用受控来源与真实 SQL；不声称真实供应商完整验收。
