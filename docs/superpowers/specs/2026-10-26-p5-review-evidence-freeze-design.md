# P5-03 第二批：复核证据授权读取与固定保存

日期：2026-10-26  
状态：用户已确认方案范围；书面设计已自审，待用户审核。尚未实施。

## 1. 目标与已确认范围

接续已完成的复核内容投影，将同一用户、Case、报告、批准交付、实施版本及已保存证据组装成不可变的复核输入。后续新 Verified 报告可以明确引用本次输入，而不是在生成过程中不断读取“最新数据”。

本批只实现内部服务端来源解析、验证、原子保存和授权读取，不新增公开接口、页面、SEO 决定编辑、生成任务或收费入口。调用方必须提供来自可信认证上下文的 owner ID，不能把浏览器传入的 owner ID 当作身份。

成功保存表示证据已固定，不表示报告已生成、SEO 已批准下一步或客户已收到交付。

## 2. 方案选择

- 采用分步接线：先完成证据存储边界，再接生成、结算和交付。权限、版本和重试可以独立验证。
- 暂不采用一次贯通数据、生成、扣点和交付：涉及多个独立状态机，不利于隔离故障。
- 不接受浏览器上传完整证据后直接保存：checksum 只证明内容一致，不能证明记录来自授权存储。

## 3. 输入契约

新增严格的内部选择契约，禁止额外字段。外部选择只能指定已有来源，不携带报告正文、数值、资格判断或决定。

选择包含：

- 原报告 ID 与预期 checksum。
- 批准交付 ID、revision 与预期 checksum。
- 实施记录 ID、revision 与预期 checksum。
- 按批准行动顺序排列的逐行动选择，最多三项；每项包含 action ID，以及可选的当前/前次页面检查 ID、GSC 冻结对比 ID、GA4 采集任务 ID。

每个批准行动恰好对应一项选择；没有批准行动时允许空列表，不补造行动。没有某类证据使用明确的 null，不用空对象或虚构零值。前次页面检查不能在当前检查缺失时单独出现。

请求 ID 与选择分开传递；Case 和 owner 来自可信调用上下文。规则版本由服务端固定为现有复核投影规则，不由请求方任意指定。请求大小上限 32 KiB；完整 bundle 继续沿用 2,000,000 字节上限。

本批 bundle 的 decisions 必须为 []。禁止以隐藏字段方式接收理由、完成声明或新行动；现有投影自然输出 needs_review。未来决定功能需要独立记录来源、审核和版本设计，不能就地修改本批证据。

## 4. 来源解析与授权

复用现有 `app/report_v22/` 验证规则及数据库来源，不另建宽松资格算法。

1. 确认 Case 存在、未归档且属于可信 owner；报告属于同一 Case 和 owner，并满足现有完成报告条件。
2. 读取指定的已批准交付版本，校验其原报告 checksum。使用批准后的行动，不恢复原始生成行动。
3. 按实施记录 ID 和 revision 精确读取，不能依赖最近 20 条历史列表来寻找旧版本；校验其报告、交付和 owner 绑定。
4. 页面来源必须来自已完成且与 observation 一致的保存任务。允许 observation 本身包含检查失败或受限状态；不把未完成任务当成观察。
5. GSC 来源必须为已保存的 FrozenComparison，精确绑定实施版本和行动；保留原窗口、范围、评估时间及受限原因。
6. GA4 来源必须为已有成功终态任务及其完整保存结果，精确绑定实施版本和行动；成功采集不等于数值具备解释资格，资格仍交给现有阅读器。
7. 复用第一批验证器检查站点、行动、时间、重复冲突 ID、数值边界及源 checksum。不能只依赖数据库 ID 存在。

未选择的可选来源可以缺失；明确选择的来源不存在、无权读取或绑定不符时，拒绝整次保存，不能静默降级成 null。

## 5. 历史版本与时间语义

本批是历史证据固定，不是“取得最新状态”的入口。允许明确选择仍存在且可授权读取的历史批准交付和实施版本；不要求它们为最新版本，不偷偷升级版本，也不将历史业务范围替换为 Case 当前范围。

保存包使用所选原报告的业务范围，并要求全部证据与该范围一致。当前 Case 的修改不会自动重写报告范围。未来生成入口是否允许基于该历史范围继续生成，需要其独立的当前状态确认，本批保存不提供生成资格承诺。

历史 GSC/GA4 结果不重新调用 Google、不检查当前授权来重新计算过去的资格，也不声称 Google 现在仍可访问。Case 的当前 owner/未归档条件始终适用。来源实际被删除或依既有安全规则不可读时，新保存失败，不恢复已删除内容。

evaluated_at 由可信服务端产生，固定于本次解析；保存时间由数据库记录。首次保存要求 evaluated_at 在既有存储常用的时钟容差内：不晚于当前时间一分钟、不早于当前时间五分钟。超过容差需要重新解析，不能挪动来源时间。

已经成功保存的重试返回原 evaluated_at 和原保存时间，不受首次保存时间窗影响。

## 6. 数据流与原子性

采用“解析 → 纯验证/组装 → 事务内重验并保存”的流程。

### 6.1 解析

服务端按选择读取可信来源，返回构建 bundle 所需完整内容及 Case 状态守卫（当前 updated_at）。读取时检查每条来源的精确身份，不按 latest 补全。解析不创建持久化草稿，也不占点。

### 6.2 组装

后端复用 ReviewEvidenceBundle 与 build_review_projection 的校验，构建 decisions=[] 的完整输入，计算 evidence_checksum、bundle checksum；解析结果和投影均保持分离，不把投影摘要作为原证据保存。

### 6.3 事务内保存

数据库保存函数必须：

1. 对请求 ID 使用事务级串行化锁；检查当前 Case 权限，即使请求已经保存也不能跳过授权。
2. 若已存在同 owner、Case、请求 ID 且选择完全一致的记录，返回原记录；若同 ID 内容不同则冲突。跨 owner 的同 ID 不泄露原记录或其内容。
3. 首次保存按 Case → 报告顺序锁定并重新检查授权和完成状态，与现有页面检查的锁顺序保持一致。只读已保存历史证据，不申请 Google connection 锁。
4. 重新读取选定批准版本、实施版本和每项来源；比较解析时的 Case updated_at。期间 Case 变化则返回可重试的 stale，不自动换版本。
5. 将提交 bundle 的每个来源字段与数据库重读结果逐项核对，验证身份、选择、版本、时间、规则及 decisions=[]。不能仅相信服务端传来的 checksum。
6. 验证完整内容与规范文本一致且 hash 正确后，一次性写入保存包和元数据；任一步失败整笔回滚。

同一事务并发归档/转移 owner 时，按照锁获得顺序形成明确先后：保存若先完成，随后失去权限则不得继续读取；权限变更若先完成，保存应拒绝。

## 7. 保存格式与完整性

新增内部不可变记录表 `capability_review_evidence_bundles`，主要字段为：请求 ID、owner、Case、report ID、delivery ID/revision、implementation ID/revision、选择 JSON、bundle JSON、无损传输文本、规范 hash 文本、两类 checksum、evaluated_at、frozen_at、schema/rules version。

输入与选择只保存一份确定版本，不提供 UPDATE 路径；需要重新选证据时使用新请求 ID。RLS 与权限沿用已有来源存储模式：撤销 public/anon/authenticated 直接读写，可信服务仅通过受限保存/读取函数写入；不暴露公开存储地址。

必须区分两种序列化：

- 无损 bundle 传输沿用 legacy-preserving canonical_json_bytes，保留旧来源所需的浮点表示。
- 复核 evidence/bundle checksum 沿用第一批 verified_request_digest 规则。

不能用会将 3.0 改成 3 的规范化文本替代原始来源传输。数据库可另存 JSONB 用于结构比较，但读取返回保留源数值表示的文本；两份表示必须校验为同一内容。摘要文本必须按既有规范规则验证，不能只比较摘要文本声称的 hash。

读取重新执行 Case 授权、外层 owner/Case/ID 绑定、内容 hash 和完整 bundle 验证。内部损坏时拒绝，不返回半份可用投影。已保存包是历史快照，不因来源后来新增版本而重算；本批不引入新删除/保留政策，继续遵循既有数据生命周期。

## 8. 模块边界与错误

后端新增小型选择/保存契约、仓储适配与固定输入服务；复用纯投影，不扩展其 I/O 职责。数据库增加来源解析、事务保存和精确读取函数及迁移。函数仅限可信服务调用，本批不增加浏览器可达的 API 或页面。

错误分类固定为：invalid、unavailable、conflict、stale、too_large、storage_unavailable。unavailable 合并不存在和无权访问的外部表现；不回显来源正文、Google 资源标识或数据库异常。存储瞬时故障使用原请求 ID 重试；stale 需要重新解析；选择改变需要新请求 ID。

保存前后均不触发 provider、抓取、队列、模型、生成或点数操作。失败不会产生保存包；成功不会产生报告。保留当前 review 生成入口、输入解析和结果持久化的拒绝保护。

## 9. 验收要求

实施前记录两仓工作基线，只修改本批相关文件，保留全部既有未提交工作。

1. 正常 bundle 从真实本地测试存储来源解析、验证、保存、读回；与纯投影结果一致。
2. 精确历史版本可用；最近列表之外的实施版本可定位；新版本不会覆盖旧包。
3. 跨 owner/Case/report/delivery/implementation/action、站点错配、未批准交付、未完成来源全部拒绝。
4. 缺少可选来源、受限数据、失败页面观察、零行动报告保持准确状态，不强行创建建议。
5. SQL 保存直接提交伪造来源、伪造 hash 文本或非空 decisions 时拒绝；不能绕过后端验证获得可信包。
6. 相同 ID/选择重试恢复原结果；不同选择冲突；同 ID 并发只产生一条记录。
7. 解析后归档、owner 变化、Case 更新、来源删除在保存重验时被捕获，无部分写入。
8. 保存后归档/失权的历史读取和重试同样被拒绝，不通过恢复路径泄露数据。
9. 当前时间、超时重试、未来来源、超额字段、重复行动/来源和大小边界均覆盖。
10. 浮点与整数、JSONB 往返、传输文本和 hash 文本分别测试；旧来源 checksum 不变。
11. 本地原生数据库测试验证 RLS、直接写入禁用、不可变性、事务回滚、锁顺序与并发；不能仅用 mock 声称完成。
12. 后端快速回归、既有契约导出校验通过；若增加前端镜像契约则执行其类型与契约测试。无 UI 变更不宣称新增浏览器流程已验收。
13. 副作用断言确认没有真实 Google 调用、抓取、模型、收费、队列派发或旧报告修改。

若本地原生数据库环境不可用，应明确记录未验证项，不能将本批称为全部验收完成。
