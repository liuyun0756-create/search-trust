# P5 页面检查：授权加载、独立保存与恢复

日期：2026-10-23。

状态：用户已确认书面方案（“可以开始”）；内部实现与隔离验证完成，不开放产品入口。验收见 `../plans/2026-10-23-v22-capability-p5-page-check-persistence-verification.md`。

## 1. 本批目标

把已完成的单页检查器接到可验证的数据库来源和独立任务记录，使同一请求可恢复、历史证据不可覆盖。

本批只做内部闭环：来源解析、请求入库、单次领取、执行、结果保存、所有者读取和受控过期处理。新增迁移仅在本地隔离数据库应用；不注册公开 API、页面按钮、队列派发或定时任务，不调用真实客户网站，不部署，不修改实际开关。

本批不新增扣点，也不宣称未来页面检查免费无限量。开放入口前另行明确运行频次与成本规则。D1 正常完成但依据不足仍交付诊断、消耗 1 点且不返还；原技术失败规则不变。

## 2. 方案与复用边界

采用独立页面检查任务与不可变观察表，沿用现有 GSC/GA4 的单次领取、原请求恢复和服务端私有事务模式。

不混入普通站点同步：普通同步更新最新来源，不能表达某次实施修订及指定检查条件。
不直接同时搭建用户入口：先验证真实数据库并发与恢复，再设计确认和状态交互。

现有依据：

- 后端 `page_implementation_models.py`、`page_implementation_checks.py`、`collectors/page_implementation.py`：已验证的计划、观察、比较及受控 GET。
- 后端 `comparison_storage.py`、`ga4_collection_storage.py`、`ga4_collection_executor.py`：有响应大小限制的 RPC、单次领取和恢复模式。
- 迁移 `20261022110000_record_v22_implementation.sql`：报告级锁、批准来源验证、实施记录不可变修订。
- `case_business_scope_versions`、`capability_report_versions`、`report_content_revisions`：业务范围、完成报告及批准交付的实际来源。

只复用模式，不复用 GA4 身份、连接权限、任务表或普通最新来源选择逻辑。单页检查本身不需要新增 Google 权限。

## 3. 输入与服务端来源

内部请求包含：请求 UUID、实施记录 ID/修订/摘要、行动 ID、明确目标 URL、1–5 个已支持的检查条件。所有者与 Case 来自可信服务端调用上下文，不相信任意请求正文中的身份。

数据库解析返回：已完成 Verified 报告及摘要、指定已批准交付及版本、完整实施记录、报告绑定的业务范围、当前 Case 版本标记。后端使用现有准备函数重建检查计划；数据库再次核对计划引用、条件、URL 和规范化内容摘要。

必须满足：

1. 当前所有者拥有处于 active 状态的 Case，报告完成且交付批准；来源摘要和交付 source_checksum 一致。
2. 所选行动同时存在于批准交付和所选实施记录。
3. 实施修订是该批准交付下最新保存的一版；不能只按记录根 ID 判断最新，需检查 delivery_revision_id 下的修订序号。
4. 报告业务范围与数据库保存版本一致，且仍是当前确认范围；新的业务范围版本使旧计划不再具备新检查资格。
5. URL 与条件通过上一批规则：同一明确主机、HTTPS、无凭据/查询参数，不能从 scope 说明文字猜测 URL。

缺失或不一致时，任何网络请求前拒绝。核验摘要只是完整性检查，不代替所有权。SQL 只处理结构与确定性边界，不执行 DNS 或 HTTP。

## 4. 数据模型与权限

新增两张独立表（确切名称在实现计划中采用以下名称）：

- `capability_page_check_jobs`：请求 ID、所有者/Case/报告/交付身份、实施引用、固定选择、固定计划、来源版本标记、状态、领取凭据及时间、结束时间和有限错误码。
- `capability_page_observations`：一对一任务 ID、固定观察正文、摘要及保存时间。

选择与计划创建后不可修改；任务状态仅允许规定方向变化，终态不可改写。观察表拒绝 UPDATE/DELETE；新检查生成新任务和新观察。

RLS 开启；匿名和普通登录角色不能直接读写，service_role 不获得表直接写权限。仅授予必要私有事务函数执行权限，内部辅助函数不开放执行。源表和原业务权限不放宽。

请求 UUID 同所有者范围不发生隐式重绑定；不同人碰撞同 ID 返回通用不可用错误，不泄露他人任务或目标。与分析任务/普通同步用途保持隔离，不把页面检查 ID 当分析 job_id。

每个 Case 同时最多一项 queued/running 页面任务，这是内部并发保护，不是对外套餐额度。请求选择上限 20 KiB，计划/观察分别上限 64 KiB；完整来源读取上限 2 MiB，单任务读回上限 128 KiB；历史最多 20 项摘要，详情按 ID 单独读取。

## 5. 状态与执行

任务状态使用 queued、running、completed、failed；观察内部仍使用 checked 或 unable_to_check。

| 情况 | 任务状态 | 观察记录 | 再次访问网站 |
| --- | --- | --- | --- |
| 已确认，尚未领取 | queued | 无 | 只有成功领取后才允许 |
| 唯一执行者已领取 | running | 无 | 本次最多一次受控检查 |
| 正常检查并保存 | completed | checked | 不自动重查 |
| robots 禁止、超时等已形成明确观察 | completed | unable_to_check | 不自动重查 |
| 源版本失效、执行中断或内部执行异常 | failed | 无 | 不自动重试 |

页面访问超时若已由检查器返回完整的 unable_to_check 观察，可正常保存。进程被取消/丢失、未拿到完整观察，则不能制造一份成功或“未修改”的结果。

内部执行器先通过数据库原子领取，再调用现有检查器；沿用最多两个 GET、整体检查 30 秒、不跟随重定向、只保存有限事实的规则。不执行大模型分析，不写普通同步或任何交付内容。

领取凭据一次性，执行租期 2 分钟，覆盖 30 秒检查与结果验证保存。queued 请求超过 10 分钟未领取失效；running 超过租期转为 interrupted。过期处理通过明确内部事务完成，只标记失败，绝不抓取或重新排队；本批不注册后台清理任务。

只读获取状态不会发起检查、续租或改变结果。读取可以同时返回 derived expired 提示，但数据库实际状态只由状态事务推进；不能把提示当作自动重试授权。

## 6. 并发、来源变化和恢复

相关写事务采用一致的锁顺序：Case → 报告 → 页面任务。报告锁与现有实施记录保存的报告级锁协调，防止检查保存同时发生日期修订时漏查版本。锁内不做外部请求。

请求创建、领取、保存都重新检查当前来源。新草稿本身不改写指定旧批准交付；但实施修订、确认业务范围或 Case 版本变化，会阻止尚未完成的旧检查成为有效结果。

已保存终态观察在实施修订或业务范围更新后仍可按原报告/交付所有权读取，始终展示原绑定，不自动迁移到新版。Case 失效或访问权丧失不允许读取；终态可读不要求其来源仍是最新版本。

恢复规则：

- 同请求 ID、同选择重复确认：返回原任务，无新网络访问。
- 同 ID、不同选择：冲突；不得覆盖原计划。
- 创建成功但确认响应丢失：按原 ID 读取或重发同一确认，恢复原任务。
- 领取成功但领取响应丢失：其他执行者不能再次领取；到期记录 interrupted。
- 执行中取消：不自动重试；由到期事务结束。
- 保存成功但响应丢失：读取已保存结果；重复提交同凭据、同完整结果也返回原结果。不同结果即使 ID 相同也冲突。
- 保存未成功但执行者仍持有完整观察与有效租期：可重试同一保存；不重新抓页面。
- 无法恢复完整观察或租期已过：失败结束。再检查必须显式新请求。

相同请求的恢复仍需当前读取权限，但不因为实施修订已变就偷偷创建另一项任务。

## 7. 保存与读回验证

观察 ID 必须等于任务 ID，完整 plan 必须等于冻结计划。观察时间不得早于领取时间和实施记录时间，不得晚于数据库保存时刻；服务端统一输出 UTC，不依赖数据库会话时区。

后端重验观察契约及规范化摘要；SQL 核对必要字段、精确绑定、状态组合、结果条件顺序、有限错误码、时间和大小。不能仅重签错误数据就绕过验证。

completed 必须且只能有一份观察；failed 不允许附带部分观察。完成标记与插入观察在同一事务内提交，不留下“有成功状态无结果”或“有结果仍可再次执行”的窗口。

读回重新验证所有者、任务/计划/结果一致性及摘要。不可信存储响应、超大响应、无效类型或不一致状态返回有限内部错误，不把原始异常传给未来页面。

旧观察比较继续调用上一批纯函数。本批只提供按 ID 授权读取，不自动挑选“最有利”的基线，也不把旧观察提升为当前证据或效果结论。

## 8. 预计实现与测试

后端新增 selection/job 契约、授权仓储与单次执行器；前端仓库新增增量迁移；既有内部测试适配器只增加必要 RPC 支持。保持本批模块与现有采集、报告、账本解耦。

验收覆盖：

1. 多连接同时确认相同 ID 只生成一项；不同选择复用 ID 冲突；同 Case 活跃任务并发受限。
2. 多执行者只有一次领取成功，重复领取及领取响应丢失不会多发 GET。
3. 跨用户/Case/报告/交付/实施版本、错误行动、业务范围变化、无批准来源，均拒绝。
4. 创建后、执行中、保存前来源更新与权限变化的竞争场景。
5. checked 和 unable_to_check 均可形成 completed；执行故障、取消及过期不能误作页面未修改。
6. 同请求、同保存响应丢失恢复；不同保存冲突；旧观察不能更新、删除或换绑。
7. 只读查询零网络、零点数变化；新表不可由匿名/普通用户/service_role 直接写。
8. 非 UTC 数据库会话、错误时间、结果身份/条件/摘要篡改、大小上限与无效返回。
9. 原报告、分享、批准交付、实施日期、GSC/GA4 来源和点数保持不变。
10. 后端 fast、隔离原生数据库/Redis/ARQ 回归与旧契约检查；没有 UI 改动不宣称浏览器验收。

HTTP/DNS 全部模拟；迁移仅应用到新建隔离数据库，不修改正式环境。测试结果完成后另写验收记录，不提前标记通过。
