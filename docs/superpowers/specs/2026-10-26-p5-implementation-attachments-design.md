# P5 实施记录附件设计

日期：2026-10-26  
状态：用户已于 2026-10-26 确认书面设计，本地实施与验收已完成；未启用、未部署，真实 Storage 验收仍待授权。

## 1. 本批目标

让独立 SEO 为已保存的实施行动附上截图或文件，并在原实施版本中查看、下载。附件是用户提供的工作材料，不代表系统验证实施完成，更不代表产生 SEO 效果。

用户已确认的范围：可选上传、查看、下载、Case/行动/版本绑定、历史追溯、安全与权限校验；保存不额外扣点。

不包含：附件内容分析、OCR、客户分享、报告 PDF 嵌入、自动抓取、Google 取数、收费复核、真实环境开关变更或部署。

## 2. 调查依据与方案取舍

- 现有 `ImplementationRecords.tsx` 提供免费保存与历史记录，最多显示最近 20 个实施修订。
- `ImplementationRepository` 校验完成的 Verified 报告和批准交付；数据库对原实施记录禁止更新/删除。
- 原实施记录摘要被页面检查和比较结果引用，不能为补附件改写旧 payload/checksum。
- 当前前端有 Supabase 客户端依赖，未发现可复用的实施附件模块或 Storage bucket 迁移。

推荐：**私有对象存储 + 独立附件登记/生命周期 + 精确实施版本关联**。沿用现有所有者权限，文件不进入原记录 JSON。

不采用：把二进制或 Base64 塞进实施记录（负担数据库并污染历史摘要）；仅保存外链（失效、权限及第三方跟踪不可控）。

## 3. 体验和文案

### 当前记录

已保存的每个行动下增加 `Supporting files · optional` 区域，显示其实施修订编号。未保存时说明 `Save the implementation record before adding files.`，不接受暂存文件。

说明：`Add screenshots or documents of the work you published. Files support your record; they do not verify completion or SEO results.`

上传按钮：`Add a file · no credits used`。

文件项显示安全处理后的名称、类型、大小、上传时间和状态，提供 `Download`、`Remove`。上传状态单独展示，不阻断原记录的读取或保存。

成功：`File attached to implementation revision {n}. No credits used.`

失败：`The upload could not be confirmed. Check this upload before trying again.` 保留请求编号供恢复；不自动创建第二份附件。

历史记录内可展开同一修订/行动的附件清单。新增实施修订不自动复制附件，也不暗示旧文件支持新范围；旧版本仍可查看和下载。修改表单中的日期或范围不会重绑定已上传文件。

### 移除

移除前确认：`Remove this file? It will no longer be available from this record. The implementation record and report will stay unchanged.`

移除后保留最小状态记录，显示 `File removed`；文件内容不可再下载。不提供在新版本中覆盖旧文件的操作。

首版沿用现有实施记录样式，不新增独立任务板或视觉方案选择。

## 4. 文件范围与配额（首版建议值）

- PNG、JPEG 和 PDF；单文件最大 2 MiB，禁止空文件。
- 每个实施修订的每个行动最多 5 个有效或占位中的附件；同一 Case 有效/占位容量上限 100 MiB。
- 新上传占位每个 Case 滚动 24 小时最多 20 次；恢复同一请求不重复占次。
- 文件类型、扩展名、声明 MIME 和文件签名必须匹配；名称长度最多 160 个字符，去路径和控制字符。
- 图片和 PDF 均作为下载文件提供，不内嵌浏览器渲染，不执行脚本或读取文档内容。
- 文件签名检查不是杀毒；首版不宣称完成恶意文件扫描。UI 提醒仅上传有权使用的工作材料，不上传密码或不必要的客户个人资料。

这些限额是文件安全/容量限制，不是新增计费商品；实现和文案共享同一套常量。

## 5. 权限与存储

- 新独立功能开关默认关闭，并依赖既有实施记录权限开关。
- 专用私有 bucket，无匿名或浏览器直接读写权限，无公开 URL。
- 服务端生成不含文件名、邮箱或客户名称的随机对象键；不得接受客户端对象路径或远程 URL。
- 所有操作从会话取得用户身份，验证 Case、完成的 Verified 报告、批准交付、实施记录 ID/修订/摘要及行动归属。
- 新上传只允许绑定提交时最新的实施修订中已记录的行动；预留和最终确认均复核。旧修订只读和移除，不能补传改变历史材料。
- 下载每次经所有者端点鉴权后由服务端读取私有对象，不返回长期凭证或公开地址；设置 attachment、nosniff、private/no-store 和安全文件名。
- 写请求必须同源，限制读取体积和超时。越权 ID 返回统一不可用响应，不泄漏其他账户文件存在性。
- 数据表和辅助函数遵循现有最小权限；service role 仅在服务端使用，浏览器无直接表写权限。

## 6. 上传事务、恢复和清理

1. 浏览器生成上传请求 UUID，保存最小请求上下文，不持久化文件内容。
2. 服务端验证来源并在 Case 锁内预留配额，冻结实施版本与行动；相同 UUID/同元数据恢复原状态，不同内容冲突。
3. 服务端限量读取实际字节，校验大小/类型并计算摘要，写入私有对象，禁止覆盖已确认对象。
4. 最终确认再次校验来源和对象摘要，原子登记为可下载；响应丢失后按原 UUID 查询，不重新上传或重新扣配额。
5. 预留后 15 分钟未确认的任务失效；不因为普通读取而推进状态。后续显式清理作业处理过期占位和遗留对象。

数据库与对象存储不是同一事务。中断时先阻止文件被下载，保留可重试的清理登记；对象删除确认前不释放相应存储占位，避免低估容量。

删除先撤销可下载状态，再删除精确对象；失败保持不可下载并可恢复删除，不回滚成有效附件。日志只记随机 ID、状态和有限错误码，不输出文件字节、签名地址或原始异常中的敏感信息。

## 7. 不可变历史与后续复核

附件登记固定关联原批准交付、实施修订和行动，记录服务端上传时间及字节摘要。上传时间与用户填写的实施日期分开，附件不得追溯伪装成当时已存在的材料。

原实施记录、报告、比较结果和页面检查 checksum 完全不变。附件集合有独立版本；未来收费复核须显式冻结所选集合及摘要，本批不自动注入复核输入。

移除文件不重写原实施记录。历史引用只能说明该附件曾登记且现在已移除，不能继续声称文件可用；不把删除前的内容放进可访问历史副本。

## 8. 实现边界

- FE：新增独立附件 contracts/repository/handlers、受保护 API、小型附件面板及开关；最小化接入现有实施记录组件。
- 数据库：新增附件/请求/生命周期及配额函数迁移，复用实施来源验证；不修改旧迁移。
- 存储：私有 bucket 配置和窄接口适配器；不把 Supabase SDK 或服务端密钥带入浏览器。
- BE：本批不修改报告生成、Google 同步、页面检查 worker 或点数结算。未来复核接线另行实施。

## 9. 验收

- 正常上传、查看、下载、移除；PNG/JPEG/PDF、错误类型、伪装扩展、空文件、超限体积和非法名称。
- 跨账户/Case/报告/批准交付/行动/实施修订访问失败；上传过程中来源变化不能挂到新版本。
- 并发配额、20 次边界、同请求恢复、不同字节冲突、存储失败、最终确认失败、清理重试。
- 刷新/断网/账户切换不自动重复上传；旧版本文件不被新记录覆盖；删除后禁止下载。
- 上传/删除不改点数、原报告、实施 checksum、比较或页面检查结果。
- 桌面/手机布局、键盘操作、上传状态公告和无横向溢出。
- 新单元/路由/隔离数据库与存储适配测试、浏览器回归、类型检查和构建。真实 Storage 集成须在获授权环境单独验收；模拟适配测试不等于真实存储验收。
