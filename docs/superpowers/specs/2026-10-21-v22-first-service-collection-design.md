# P3 首次服务公开证据准备与队列

继续已批准主计划 §4.1、§8 及首次服务启动设计；不增加收费环节、不开放页面/API、不启用生产开关。

## 调查结论与设计

现有 Prospect 采集器同时负责发现核验、四种公开来源采集及报告生成。采集阶段可以独立复用，但旧 AnalyzeRequest 的 Verified 模式要求父报告，不能移除该保护或虚构 Prospect。因此增加无 report_type/parent_report 的 FirstServiceCollectionEnvelope，只表达确认的业务、地区、查询词、竞品与真实发现引用。复用已有竞品发现（包括已支持的补充竞品），不把手填网址伪造为发现结果。本批不连接新的发现 UI 或首次服务发现收费入口。

首次服务启动仍使用上一批唯一任务和 verified 点数。内部 begin RPC 将采集意图固定到已有准备记录，核验 owner、Case、业务身份/版本、服务、地区、竞品。GSC/GA4 只读取启动时明确固定的两份快照，不选择最新替代品。采集前检查当前授权、健康和有效期，冻结及执行前继续检查。完成任务恢复不再返回私有 payload。

公开来源复用 source-only 采集入口，不调用 execute、旧报告流水线或收费接口。公共规则的历史 context 类型仍为 prospect（表示既有公开证据子模型），最终清单和报告固定 first_service / verified_execution / version 1，parent 和 previous_report 均为空。不得生成或存储中间 Prospect 报告。

网站采集器明确识别无报告的采集请求，使用公开网站/业务/地区的页面选择规则；不把新版固定 GSC/GA4 包伪装成旧 FirstPartySnapshotEnvelope。两个私有来源进入随后真实服务规则和跨来源分析。本批不新增依据 GSC 的爬取优先级算法。

独立物理队列、SQL 租约及 first_service 检查点命名空间；复用原任务截止时间、运行代数、尝试次数及成本账本。SQL 保存请求 canonical 字节和校验和，严格重放，不更换竞品/查询词。租约控制来源冻结，旧 worker 无权覆盖接续结果；冻结后交接既有正式 dispatch。交接响应丢失走 ready 恢复，禁止重新采集。失败不在异常处理里盲目退款，由既有原期限恢复事务负责；正常零行动诊断仍消费一点。

## 验证边界

实际数据库迁移测试：重放、授权失效、来源固定、owner/意图冲突、租约竞争/过期/旧令牌、冻结/ready 恢复、私有数据不向浏览器开放及同一次收费。后端测试：真实来源适配器/服务生成器、采集协调器与队列故障路径；外部供应商由固定来源替代，不发送真实采集请求。

未完成项保留：首次服务页面、连接中心模式、新发现入口与扣点前全量输入校验、生产数据库/Redis/Google/登录环境验收。无历史服务入口不以本批内部接线宣称上线。
