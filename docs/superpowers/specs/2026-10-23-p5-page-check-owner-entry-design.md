# P5 页面检查：确认入口、状态、历史与限频

日期：2026-10-23。
状态：2026-10-26 用户确认书面方案，同日完成本批本地实现与隔离验收，见 [验收记录](../plans/2026-10-26-v22-capability-p5-page-check-entry-verification.md)。规则保持“不额外扣点、每 Case 滚动 24 小时 10 次、新检查间隔 5 分钟”。默认关闭、未部署，不代表 P5/P6 整体完成。

## 1. 本批目标与明确不做

把已经验证的页面检查保存层接到报告页，让独立 SEO 能明确选择检查目标、确认一次检查、恢复状态和查看原始历史。页面沿用实施记录区域现有表单及结果样式，不做营销页面或独立视觉改版，也不增加一个需要学习的新工作台。

本批包含默认关闭的前端入口、所有者接口、后台受控派发、过期清理和服务端限频；仅本地隔离测试，不开启实际环境开关、部署或应用正式迁移，不访问真实客户网站。

不修改报告、PDF、分享、实施日期和 Google 数据；不把页面条件命中当作实施全部完成或效果证明；不自动生成新版报告、自动选择对比基线或运行收费复核。D1 正常完成但依据不足仍交付、消耗 1 点且不返还的规则不变。

## 2. 已确认的使用规则

页面检查首版不额外扣点，不调用大模型。它是已批准交付和已保存实施记录下的有限检查，不是免费全站审计或无限监控。

- 每个 Case 同一时刻最多一个 queued/running 任务，延续现有并发保护。
- 同一 Case 每滚动 24 小时最多创建 10 个新检查；两个新检查的创建时间至少相隔 5 分钟。
- 所有报告、交付修订、行动和目标 URL 共用该 Case 的限制；更换行动、URL、修订或浏览器不会重置次数。
- 以数据库成功创建任务为计次点。完成、无法检查、后续失败或过期的已创建任务均计一次，避免失败后无限重试。校验拒绝、限频拒绝、创建事务回滚不计次。
- 同请求 ID、同选择恢复原任务，不重复计次，也不要求重新满足冷却时间；不同选择不能复用该 ID。
- 查看状态和历史不扣点、不计次、不发起页面访问。
- 限制以数据库时钟计算，不按本地自然日重置。创建时间恰好满 24 小时的记录移出窗口；恰好满 5 分钟可再次申请，但仍须满足其他条件。

界面展示滚动窗口内已用次数和最早可再次请求的时间；剩余次数是当前快照，不是预留，提交时重新校验。活跃任务未结束时单独提示等待，不仅给出倒计时。

这是经用户确认的初始产品限制，并非真实成本测算结果；本批不新增账户级套餐额度或将其宣传为无限使用。正式开放仍需后续真实环境与容量验收。

## 3. 方案选择与现有依据

采用“独立页面检查面板 + 独立入口契约”，嵌入报告的实施记录区域。

不把它塞入 GSC/GA4 比较结果：两类结果意义不同，页面静态观察不能获得指标可比资格。不采用自动检查/定时监控：所有新任务必须来自 SEO 的显式确认。收费检查方案本次未采用，用户已选择不额外扣点并限频。

复用：

- `page_check_storage.py`、`page_check_executor.py` 和第 68 个迁移：授权绑定、不可变结果、唯一领取和恢复。
- `ImplementationRecords.tsx`：保存的实施记录、批准交付绑定和表单样式。
- `ga4_collection_entry.py`、GA4 BFF/组件及 worker：所有者投影、前后端契约、确认与恢复、只派发已有请求的模式。

仅复用模式，不扩大旧比较结果联合类型，不将新的 HTTP 检查挂在 Google 连接权限或 GA4 开关下。

## 4. 所有者入口与数据流

读上下文时核验当前用户、active Case、完成 Verified 报告和指定批准交付；读取该交付的最新实施记录、明确的网站主机、所选报告/交付下最近 20 个历史任务摘要，以及 Case 范围限频状态。

历史读取仍使用原绑定，不要求它是最新实施修订。当前业务范围改变、没有有效实施条目或当前来源不具备新检查资格时，返回可理解的“暂不能新检查”状态，不能因此抹掉仍有权查看的历史。

提交前，后端先核对路由报告/交付与选择中的实施引用一致，再解析来源和入库。不能先为另一个报告创建任务，再在返回视图时拒绝。数据库是权限与次数的最终裁决，不相信前端携带的所有者、余额、时间或来源摘要。

详情投影只给出用户需要的任务 ID、选择、实施修订、目标、条件、时间、状态、有限原因和观察结果。不向前端暴露领取凭据、完整来源报告、服务端令牌、HTML 或内部异常。

## 5. 报告页面内容与交互

新增面板位于实施记录之后，与指标比较并列，不依赖指标比较已经加载成功。

### 默认状态和输入

- 标题：`Check the published page.`
- 说明：`Check specific text, a same-site link or an anchor on one page. This checks the static response, not rendered behavior or SEO performance.`
- 已保存的行动选择器；只有最新实施记录中的行动可用于新检查。
- 显示批准交付版本、实施记录修订和确认的网站主机。
- `Page URL`：初始为空，由 SEO 明确填写；不从行动说明或实施 scope 猜测，不默认其他主机。沿用 HTTPS、同一明确主机、无查询参数/凭据的规则。
- `What should we look for?`：1–5 项条件，类型为 `Text`、`Same-site link`、`Anchor ID`。初始一行 Text，值为空，可添加和删除；不自动生成或暗中改变检查内容。
- 未默认勾选的确认：`I confirm this page and these checks match the work I recorded.`
- 按钮：`Check this page · no credits used`。
- 限频提示：`Up to 10 checks per Case in a rolling 24-hour period. Wait at least 5 minutes between new checks. Accepted requests count even if the page cannot be checked.`

行动、目标、条件、实施修订或授权上下文变化时清除确认；未保存实施记录、来源过期、输入无效、已有活跃任务、次数或冷却限制未满足时不能提交。服务端不可用时显示未知，不虚构“剩余 10 次”。

### 状态与结果

| 状态 | 页面展示 | 可用操作 |
| --- | --- | --- |
| queued | `Waiting to check` | 只读刷新状态 |
| running | `Checking this page` | 只读刷新状态 |
| completed / checked | `Page check saved` | 展开条件及历史 |
| completed / unable_to_check | `Could not check this page`，附有限原因 | 查看说明；满足限频后显式新检查 |
| failed | `Check interrupted` / `Source changed` / `Request expired` / 通用失败 | 查看说明；满足限频后显式新检查 |

条件逐条显示 `Observed` / `Not observed` / `Unable to check`。不使用“SEO 有效”“实施已完成”标签。`Not observed` 旁保留静态范围说明，避免被理解为页面一定没有该内容。

结果显示实际目标、检查时间和原实施修订。历史最多展示 20 条摘要，按需加载单条详情；不能覆盖旧结果，也不自动与最有利的历史结果比较。保留提示：`This does not verify rendered behavior, functionality or SEO impact.`

限频文案区分：`A check is already in progress for this Case.`、`You can request another check after …`、`This Case has reached 10 checks in the last 24 hours.`。时间有可读本地表达和明确时间信息，不依赖倒计时决定服务器权限。

## 6. 创建、恢复与限频事务

在创建任务的数据库事务中、Case 锁保护下执行冷却和滚动计数；不是只禁用按钮或仅在 BFF 中计算。所有能创建页面检查的服务端路径使用同一限制，不能绕过旧私有函数。

处理顺序：核对当前读取权限 → 同 ID 恢复/冲突检查 → 当前来源与选择验证 → 并发/冷却/次数检查 → 创建任务。恢复已有请求优先于新请求限频，不因达到 10 次而失去已创建结果。

使用现有任务创建时间计算，不通过可被刷新覆盖的客户端计数。并发新请求共享 Case 锁，不能两次同时通过剩余 1 次的检查。返回安全的限频原因、服务端时间及下一次可请求时间；其他 Case 的任务内容不暴露。

前端提交前保存原请求 ID 与必要选择，用账户/Case/报告/交付隔离的会话存储支持同页刷新恢复，不存令牌或来源正文。切换账户不能载入另一账户的待确认请求；恢复仍需服务器授权。

提交响应不确定时只读查找原 ID，不自动 POST 或生成新 ID。如果任务不存在，用户可以明确恢复同一确认请求；选择发生改变时先处理未确认的旧请求，不把新内容绑定到旧 ID。刷新状态、切换历史及挂载组件不创建任务。

## 7. 后台执行、过期与开关

新增独立默认关闭开关，前端/BFF、内部 API、派发扫描和 worker 都遵守；复用报告/实施记录的基础资格，不依赖 GA4/GSC 连接。关闭时没有入口或新领取；已开始的单次检查允许保存其结果，不能把开关当作取消后的自动重试机制。

后台只扫描已由用户创建的任务，每批最多 20 项。队列使用页面检查专属命名与确定性任务 ID；最多一次 worker 尝试。即使重复投递，也只有成功领取租期的一次会调用现有检查器。队列中不保存页面结果正文。

检查器仍最多两个 GET、整体 30 秒；任务 queued 10 分钟过期、running 租期 2 分钟不变。worker 包络 105 秒用于领取、检查和保存，不延长数据库租期。后台过期清理只将过期任务标记失败，不重排队、不访问页面；只读查询依然不能代替清理事务。

使用独立受控存储客户端，关闭时释放本批创建的资源。页面任务用途与分析、Google 同步/采集队列隔离，不接入旧收费任务或自动复核。

## 8. 接口、权限与错误边界

后端采用独立 page-check entry/service 投影及内部认证路由；前端使用独立 BFF 与严格共享契约。复用现有会话认证、同源写入检查、无缓存、有界正文/响应与服务器端凭据传递模式，不放宽旧比较接口。

本批新增命令形状只表达 context/read/request；用户 ID 来自可信会话链路，不从浏览器正文接受。读详情还需精确核对 Case/报告/批准交付，不能凭任务 UUID 读取其他来源。

错误分为输入无效、无访问权/不存在、来源冲突、限频和暂时不可用。限频使用明确的 429 和有限原因，BFF 不将它错误折叠为“服务异常”；其他异常原文不透出。结果与来源摘要仍在服务端重新验证。

数据库迁移保持增量；仅必要事务允许 service_role 执行，新表直接写权限与内部辅助函数隔离不放宽。

## 9. 验收与工作保护

新增测试覆盖：

1. 10 次上限、恰好 24 小时边界、5 分钟边界、所有行动/交付共享 Case 限制、失败/无法检查计次，以及同请求恢复不计次。
2. 并发只剩一次额度、已有活跃任务、限制期间仍可读历史、拒绝和回滚不占次数。
3. 所有者/报告/交付/实施错配在创建前拒绝，来源改变后禁止新检查但原有历史按权限保留。
4. 开关默认关闭、禁止跨站写入、请求/响应大小限制、无令牌/源正文泄露、429 安全传递。
5. 模拟浏览器下默认不勾选、输入变化取消确认、挂载/刷新/历史零新请求、响应丢失与同 ID 恢复、账户/路由隔离、无自动重新检查。
6. 真实隔离数据库/Redis/ARQ 的派发、重复投递、中断、过期和保存恢复；HTTP/DNS 全模拟，证明最多单次受控访问。
7. 桌面/手机、键盘、标签和状态公告；保持已批准报告、点数、实施记录、GSC/GA4 和普通同步不变。

执行前另写逐项实施清单；完成后跑后端 fast、原生集成、前端测试/类型/构建、旧新契约及相关浏览器测试，记录实际结果，不预先标记通过。P5/P6 和总计划仍保留其他未完成项。

已按 brainstorming 自审：计次与收费分开、恢复与新检查分开、历史权限与最新来源分开、只读与过期清理分开；没有自动效果判断或发布承诺。测试中的时间推进只操作隔离环境。
