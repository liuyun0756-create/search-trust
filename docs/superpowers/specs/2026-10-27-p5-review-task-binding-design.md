# P5-03 第七批：复核输入与任务绑定

沿用用户确认的下一步方向。本批完成数据库持久化和执行读取边界；正式报告契约、结算、派发与交付仍是后续依赖，不把中间候选当作完成报告。

## 选择

新增独立、不可变的复核生成输入表，绑定已有、已预留 1 点的 Verified 任务。数据库事务内锁定活动 Case、任务和收费记录，重验冻结证据与指定决定版本，再保存原输入文本和引用 recipe。已有普通生成清单依赖普通快照，不能把本批输入伪装成该清单；也不应在 Redis 中单独保存收费任务的唯一输入。

本批不创建或扣点，不新增公开入口。预留任务仅在隔离测试建立；未来正式入口必须把任务创建、点数预留和本绑定合入同一事务后才可开放。没有行动仍交付诊断、消耗 1 点且不返还的既定规则不变。

## 数据和权限

- 单任务唯一输入；存储完整输入原文本，保持旧数值表示，同时保存内容校验和服务端计算的引用 recipe。
- 写入只接受第六批严格校验后的内部输入。SQL 独立检查字段、完整摘要、Case/原报告/证据/决定身份，与已保存记录逐项相等；准备时间必须不早于记录，与数据库时钟最多允许一分钟偏差。
- 对 active Case 和 queued/running Verified 任务加锁；run_generation 精确相等、截止时间未到；预留记录和唯一 -1 ledger 必须属于同一 user/Case/job，不能有返还或其他结算状态。
- 与旧分析输入、普通 manifest、Prospect/首次服务准备互斥；新增反向插入保护，不能先绑定复核再混入旧生成来源。
- 正式报告持久化尚未接入期间，绑定复核的任务拒绝通用 succeeded 更新，防止没有报告就消费预留点数；后续必须由带完整报告校验的事务替换该保护。
- 同任务同输入重复写入返回原记录，不改冻结时间；不同输入冲突。超时或坏成功回执按结果未知处理，恢复同任务原输入，不新建编号。
- 每次解析重验权限、任务状态、当前执行代次、账本与已保存源记录。已有记录不自动换成最新决定；新代次可以读取同一输入，但旧代次不可执行。
- RLS 默认拒绝，anon/authenticated/service_role 不可直接读写表；service_role 只能执行限定存储 RPC，内部 helper 不授权。

## 后端

独立有界 RPC repository 返回严格解析的存储回执。保存失联/畸形成功结果为可重试未知结果。解析得到带进程内来源标记的对象；复制、手造或修改对象不能作为已授权输入传入新增的 bound stage 方法。原纯内容函数仍可供测试，不注册收费派发。

限额：输入 2.3MB、返回包 5MB；拒绝重复 JSON 键、非有限数、未知字段和身份/摘要不一致。所有 SQL 错误映射到固定短码，不输出客户正文或数据库原文。

## 验收

隔离 PostgreSQL 验证正常冻结/解析、并发相同写入、冲突回滚、原决定精确读取、失联恢复、错误 owner/Case/job/代次、过期或失败任务、缺少/返还点数、不可变/RLS、双向输入互斥。报告和账本在绑定前后完全不变。后端测试验证坏回执与来源标记，生成断点消费绑定输入。复用原生测试环境；无真实收费、外部调用或生产部署。
