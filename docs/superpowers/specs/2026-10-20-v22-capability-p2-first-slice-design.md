# P2 首批实现：具体公开诊断、材料与受控修订

日期：2026-10-20。依据：已批准主执行文档 §7，用户继续执行授权与 D1 决策。本文记录该方案的实现拆分，不追加产品范围、不代替整阶段验收，不自动提交或发布。

## 本批边界

先完成公开来源到新报告的可执行生成边界、执行材料及修订存储/编辑组件。保留旧 2.2.1 worker、结算、页面和出口；不得在新结算及交付链尚未闭合时将新候选产物公开为已完成报告。首次服务、业务优先级及实施复核仍依原计划后续建设。

## 数据流与选择

冻结 manifest → 验证全部来源及完整生成输入摘要 → 复用现有公开规则 → 复用原优先级、分组及依赖选最多三项 → 以实际规则观察组装诊断与材料 → 严格契约校验 → 按原任务检查点保存候选结果。

选择确定性事实表达：原规则的对象、值、查询和限制保持原样，模板仅提供判断边界、操作结构和待确认要求。本批不新增模型调用，也不提供免费 AI 重写。旧三项选择器不变；新选择器使用相同内部规则但允许不足三项，不填充行动。

完整生成输入摘要覆盖已校验请求里的身份选择、市场坐标、查询、来源包装及分析限制。仅冻结采集快照不足以防止分析前提在重试时改变，因此新增 manifest.generation_input_checksum；生成器与原 input_checksum 分别检查，禁止冻结后重排或替换请求。

生成器仅接受 acquisition、v22_capability_public_v1 和四个合格公开来源。来源 ID、Case、schema、保存摘要、时间、资格、网站/服务/地区/竞品及完整输入摘要均须匹配。无依据提出行动仍有具体诊断、原观察和限制，settlement_policy 不变；该策略声明不等于本批已经接入实际消费结算。

## 材料与编辑

材料绑定行动、目标和证据；包含 kind、标题、正文、readiness、confirmation_items。首批为标题编辑 brief、条件式服务页 brief、公开资料纠正 brief、技术检查和可比搜索复查说明。没有已确认的页面用途或业务资料，不生成可直接发布的业务成稿。测量材料待服务报告接入，不把 schema 枚举当作已支持的生成能力。

修订允许编辑报告标题、摘要、客户说明、行动叙事、材料标题与正文。材料 ID、类别、原目标、证据引用、待确认项和状态保持系统原值，不能靠文字修改把待确认内容变成可发布。用户补充的业务信息以 SEO 说明独立呈现，不覆盖采集事实。

数据库继续追加完整修订、锁报告、防旧版本覆盖；保存不收费。原样批准及零行动批准均可。前端保存失败保留输入，冲突后阻止盲目覆盖并允许复制未保存内容；复制失败提供手动复制说明。

## 限制与验收

新契约仍为未发布的配套 2.2.2；原 2.2.1 不修改。新结构有 50 发现、500 证据、每项 20 引用等既有 P1 上限；超预算或无法最低交付时明确失败，不截断关键引用、不交付空壳。本批不宣称完成大规模结果的分页/压缩策略。

验收覆盖真实规则执行于合成保存快照、0–3 行动、不同实际响应/标题值、公开电话差异、来源和输入漂移、检查点重放/损坏、修订不可变元数据、并发冲突、保存失败、复制失败及旧链兼容。固定测试来源不是真实客户结果。

后续必须接通：新报告与任务/账本原子终结、实际阅读和编辑入口、批准版本一致的客户/PDF/分享，以及服务报告的实际规则和材料。未完成这些不勾选 P2 整阶段门槛。
