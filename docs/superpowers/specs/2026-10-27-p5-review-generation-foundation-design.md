# P5-03 第六批：复核生成输入与内容基础

依据：用户已确认继续把固定证据和指定决定版本接入新版 Verified；本批在该方向下落实生成前的独立内容基础。它不是收费入口上线，也不替代任务冻结/结算事务。

## 方案与边界

选择独立的复核生成输入及内容组装器，复用现有事实投影。两种不采用的方式：把较晚的决定写回旧证据包会改变证据时间与校验值；直接放宽旧生成器的 review 拒绝条件会让普通快照流程误接复核。旧入口、报告契约及拒绝条件均保持不变。

本批交付：精确读取已保存的证据和一个已保存决定版，产生可复现的生成输入；将事实、SEO 决定和客户可读的状态分开组装，支持版本差异和同输入断点重放。内部内容仍标记需要交付审阅，不能被现有结算器当作完成报告。下一批再增加数据库内输入/任务绑定和扣点结算。

## 输入和绑定

- 可信调用者提供 user / Case / 原报告身份，选项仅提供新任务 ID、证据 ID/校验值、决定 ID/校验值。不得读取“最新决定”替换指定版。
- 复用所有者证据和决定服务；每次准备重新验证权限及 Case。候选输入包含完整已验证的冻结记录与决定版，只有内部使用。另输出只含引用、校验值和准备时间的 recipe，供后续持久化接线使用。
- 准备时间由服务端时钟提供，晚于冻结和决定时间。证据 evaluated_at、frozen_at、报告、批准行动和原决定均不改变；本批不会为了接入晚于冻结时间的决定而重写证据包。
- 对重复 JSON 键、非有限数、非法身份/版本/来源、错误校验值、变异模型和过大正文进行拒绝。大小上限：输入 2.3MB、recipe/selection 4KB、内容 1MB、断点包 1.1MB。
- 输入完整性不等于授权或已持久化。旧任务执行器继续拒绝 review；不能仅凭内容校验值创建可收费任务。

## 内容层

保持报告类型意图为 `verified_execution`，使用独立内部 schema，而非新计费商品或冒充现有 2.2.2 完成报告。

四个部分：原批准工作及实施事实；页面变化；选定窗口指标及限制；SEO 下一步决定。前三项复用固定证据投影，不重采集或把日期重新评估到今天。下一步采用独立决定覆盖层：未选择仍未决定；继续/观察/暂缓/调整/新增均保留，原行动顺序固定，新增在后。

SEO 内容保留理由、调整目标/工作、完成说明和暂缓条件供审阅；客户候选层仅包含既有安全事实、原批准工作标题和决定类型的可读说明，不自动拷贝私人理由、实施备注、原始载荷或未审核新工作文本。客户候选并非可立即发送的正式报告。

零行动仍保留诊断与限制，不补造行动。Observe 只表达 SEO 记录完成并观察，系统核实和因果结论始终为 false；数据限制、首次基线与未选择分别展示。

## 差异与重放

由两份完整输入重新组装后比较，拒绝比较跨 owner/Case。原报告或批准版本不同则标记不可比较；无先前输入为首次基线。

事实变化与决定变化分开。仅决定版本 ID、记录时间或相同内容来源的引用 ID 变化不触发工作变化；工作内容/理由/条件/类型变化才触发决定变化。新增列表保留顺序。来源校验和输入校验仍完整保留，语义忽略不放宽绑定。

新增独立断点阶段，以规则版本、任务 ID、完整输入校验值构成键，完整验证输出及绑定后重放；损坏、异任务、异输入或重新签名但语义不符的断点都拒绝。无供应商/模型/队列/报告写入或账本调用。

## 验证与完成标准

覆盖五类决定、部分/零决定、晚于证据的决定、字段与身份错配、越权来源、精确旧版、原对象不变、私人文字不进入客户层、无变化不造 diff、跨基础不可比较、断点重放和损坏拒绝。隔离数据库验证真实保存记录可准备并组装，报告/交付/实施/账本不变。导出双端契约及合成 fixture；运行相关及全量后端回归，保留旧 review 拒绝测试。

本批不改营销页或决定工作区外观、不新增生产迁移、不调用真实账户、不启用开关，不宣称整个 P5/P6 或收费复核已完成。
