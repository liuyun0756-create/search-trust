# P5-03 第十批：复核生成入口和持久派发

沿用用户已确认的“接通真实 Case 的报告生成入口与任务派发”，不重复询问批准。应用 brainstorming 的上下文调查和边界自审；本批不做新的视觉方案。实际环境/生产数据库/部署均不改。

## 选择

复用普通能力任务的 Redis 状态机需要扩展旧报告联合类型、回调和多种状态解析，容易把 2.2.3 传给旧结算路径。纯 HTTP 同步生成无法在浏览器断开后保证交付。采用已有采集任务使用的 SQL 持久工作表 + ARQ 唤醒模式：数据库是授权、任务状态、租约和结算的唯一依据，Redis 只传递任务 ID；确定性内容无需外部模型或重复采集。

## 完整流程

1. SEO 在保存的决定版本下确认生成。命令只含请求 UUID、固定证据和决定的 ID/摘要。明确新分析需要 1 点，无行动仍交付诊断且不返还。
2. 内部服务先按同一命令查找任务，再读取所有者的保存来源并准备输入。数据库同一事务校验原报告仍为当前 Verified、无其他活动收费分析、余额和精确来源，然后创建任务、预留 1 点、保存完整固定输入及工作记录。相同命令同 UUID 可恢复；不同正文冲突；同一选择不能换 UUID重复扣点。
3. 后台定时扫描未完成工作，带有界派发租约放入独立 ARQ 函数。执行租约/代次在数据库内取得；旧代次不能读输入或完成。短暂队列/网络错误留下工作供恢复，不由浏览器返还点数。
4. 执行器读取原输入、确定性生成，再复用正式报告完成事务。报告保存、任务成功与原预留消费一起提交。响应丢失从数据库恢复，不重新生成不同输入。
5. 持久状态轮询允许刷新/离开页面。完成跳专用审阅页。技术失败或截止且没有已保存报告时，仅一次补偿；已完成结果永不返还。归档 Case 停止执行并由后台补偿未完成任务。

## 边界与验证

新前后端开关默认关闭，必须具备既有能力/决定/交付条件。公开响应不含原始输入、私人理由、服务令牌。内部接口鉴权、大小/重复键校验，BFF 同源和身份注入。数据库函数只授权 service_role，工作表不可直写。

测试覆盖并发重复、余额不足/原子回滚、来源篡改/跨所有者、同选择异 UUID、旧版本、断线恢复、派发和执行租约、代次接管、成功/失败竞态、截止/归档补偿、零行动消费、默认关闭和公开响应。原生数据库/Redis、单元、前端交互、类型和构建分别验收。多轮 2.2.3 输入适配和授权真实账户验收仍留后续。
