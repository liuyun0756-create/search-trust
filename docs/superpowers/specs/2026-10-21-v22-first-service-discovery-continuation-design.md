# 首次服务发现：同点数补充和过期刷新

继续已批准主计划及后台发现方案，不增加收费入口或部署。本批交付内部续接事务、服务端仓储、后台预算接线和回归。

## 选择与边界

不复用旧任务 ID 覆盖结果（会让迟到响应无法区分），也不创建新付费工作流。选择同一工作流内新发现 ID，保存被替换记录和续接意图，当前发现表只作为当前投影；原 charge.discovery_job_id 和 debit 始终保持不变。

补充：只能在当前发现已成功记录且仍未绑定报告时提交 1–3 个网址，与当前补充列表不同；保留 Case 身份、业务、地区和查询。刷新：仅在当前结果过期后允许，沿用原补充列表。零竞品仍不能生成报告。两种操作都明确执行，不因状态读取自动触发。

输入包括原当前发现 ID、新发现 ID、幂等键和当前就绪的 GSC/GA4 快照。并发使用 Case/charge 锁及预期当前 ID，重复意图返回原登记；同键不同输入、旧页面、新 ID 重用、已生成/已返还均不能新增任务。每轮固定私有来源引用；旧轮保留审计，新轮允许用户刷新私有来源后重新选择有效快照。

保留原三次后台执行总上限，不随人工续接清零；达到上限不启动新的采集、不扣新点、不把用户等待算作技术失败。新轮有独立 20 分钟技术期限，只能从已保存结果续接，不能用刷新延长一个进行中的任务。新轮明确技术失败仍终止并补偿原工作流一次；旧结果/旧失败请求不能补偿当前轮。

原预留回执保留初始发现身份并增加当前指针；恢复页面应读取独立 current-state 回执，过期时显示 refresh_required，不能沿用旧结果自动开始。三次用尽且仍无候选时返回明确 BUDGET_EXHAUSTED，不虚构技术失败或新增收费；公开入口上线前需要展示这一阻断及处理方式。

原始发现 ID 对应成本账本，所有轮共用。新轮不能创建或补足已丢失账本；累计成本摘要使用原始 ID 和单调账本版本更新，不能把每轮累计值重复计费。市场仍有效时复用缓存；过期时允许实际重新采集，但受原供应商额度限制。新轮不能把原检查点当成新市场结果。

继续沿用现有站点 SSRF 防护和补充核验，只接线，不扩大竞品来源范围。原有补充机制只能从已观察市场中的合格候选核验/选择，不承诺任意网址都能成为竞品。

## 验证清单

- 全迁移隔离 SQL：零二次扣点、准确重放、旧版本冲突、不可变历史、来源刷新/失效、有效结果不能刷新、旧结果和旧失败拒绝、当前绑定生成、零行动正常消费、当前技术失败一次补偿、总尝试上限和浏览器撤权。
- 后端：真实仓储/发现服务搭配受控市场来源，补充缓存复用、过期采集、共享账本/预算不重置、旧队列失效、累计摘要沿用原 ID、未知传输不退款。
- FE 仓储：严格参数与回执身份、字段白名单、当前指针与幂等重放。
- 不作真实供应商、原生并发、完整付费 UI 或生产验收声明。后续接明确使用一点的开始入口。
