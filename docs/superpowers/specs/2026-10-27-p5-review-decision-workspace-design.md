# P5-03 第五批：SEO 决定编辑与版本历史工作区

日期：2026-10-27（Asia/Shanghai）

状态：用户已认可交互原型的证据与决定并排布局；本书面设计完成自检，等待用户复核。尚未进行本批正式实现。

## 1. 本批目标与边界

把第四批已完成的独立决定版本服务接入所有者工作区：读取一个已冻结的证据快照，查看批准行动及来源，记录 SEO 决定，确认并保存，读取历史，再从最新版本明确开始编辑。

核心关系：**证据保持不变，SEO 判断独立版本化，原报告不改动。**

保存决定免费，不代表生成报告、批准交付或发送给客户。本批不接新版 Verified 生成、模型、队列、采集、分享或 PDF；不执行生产迁移、部署、真实凭据调用或环境开关变更。完整交付但缺乏行动依据的诊断报告仍消耗 1 点且不返还；本批不会触发该收费流程。

## 2. 已确认方案及备选取舍

采用三列并排工作台：窄行动导航、只读证据、决定编辑。它能让 SEO 在填写理由时直接核对来源，避免来回切页。

未采用的备选：

- 分步向导：首次引导更简单，但来回核对来源需要切换步骤，不适合反复判断。
- 侧边抽屉：保留原页面较多，但长理由、工作字段和来源选择容易拥挤，对历史版的边界也不够清楚。

已确认原型文件：`.superpowers/brainstorm/61173-1793078716/content/review-decisions-workspace-v1.html`。该文件仅用于视觉与交互沟通，演示数据不进入正式组件或正式报告。

原型不是正式行为规范的全部内容。正式实现需补齐取消决定、删除未保存新增项、真实来源范围、保存异常、冲突、权限变化、键盘导航、移动布局和草稿保护。原型中不同导航共用演示事实的做法不得进入正式版本。

## 3. 页面入口与状态

新增独立页面 `/cases/[caseId]/reports/[reportId]/review-decisions?reviewId=<uuid>`，可附带 `decisionId=<uuid>` 定位只读历史版。拒绝重复、非法及未知查询参数。

入口来自既有复核证据工作区的已保存状态；未冻结证据不显示可操作的决定编辑入口。新页面提供返回精确证据快照及原报告的链接。

页面按 owner / Case / report / review 身份隔离，跨身份不得复用状态。指定 decisionId 时必须验证该版精确归属，不允许静默替换为最新版本。

初次进入且没有历史时显示空白决定草稿，默认全部未决定；有历史时先展示最新保存版的只读摘要，用户点击 `Edit a new version` 才进入编辑。历史查询失败不能解释为没有决定，也不得据此允许以首版保存。

既有证据工作区中硬编码的 `Next-action decision: Not recorded` 改为真实状态。目录成功且为空才显示未记录；有记录显示最新版本入口；加载或失败使用独立状态。新增功能关闭时旧证据查看仍可用，但不声称不存在决定。

## 4. 布局与内容层级

### 4.1 顶部上下文

沿用既有私有工作区的绿色、浅底色和字体，不改变营销网站。

- 标题：`The evidence stays. Your judgment moves.`
- 说明：`Review what changed, decide the next move, and keep a record of your reasoning.`
- 持续可见的上下文：Case、报告版本、冻结时间、证据只读标记；历史模式显示决定版本及保存时间。
- 两个主要视图：`Your decisions` 与 `Version history`。保存后的决定为只读，不能因切回第一个选项而成为可编辑历史。

### 4.2 行动导航

展示批准行动的原顺序、标题和决定状态。未填写标记 `No decision recorded`；选择了类型但字段未完成时标记 `Draft · Incomplete`，不冒充保存成功。

新增工作使用独立 `Propose new work` 入口，不作为原行动的第五个类型。新增草稿可移除；原行动不能删除，可通过 `Clear this decision` 恢复未决定。清除已保存决定必须经新版本保存才生效，旧版保留。

### 4.3 只读证据

复用既有事实展示，包含原批准行动的目标、工作内容以及快照实际选中的页面、GSC、GA4、实施记录。每项显示可用的时间、范围、限制及事实，不只显示来源编号。

未采集、受限、不可比较和没有实施记录分别呈现，不用零值或空白冒充正常数据。保留原诊断和来源限制；较晚记录决定不改变快照当时的判断条件。

原行动仅展示其自身可引用来源；新增工作展示该快照的来源并集，并标注来源属于哪个原行动。相同来源可去重，但不得丢失行动关联。

### 4.4 决定编辑

| 决定 | 说明 | 必填补充内容 |
| --- | --- | --- |
| Continue | Keep the approved direction | 理由 |
| Adjust | Change the work or target | 理由、目标、工作、至少一个引用 |
| Observe | Review after recorded work | 理由、SEO 完成说明；快照存在此行动实施记录 |
| Defer | Set a condition to revisit | 理由、重新考虑条件 |
| New work | 独立新增工作入口 | 理由、目标、工作、至少一个引用 |

类型使用语义明确的单选控件，不是可同时选中的多选框。未决定不是 Continue。切换类型时仅保留仍合法的共用理由和引用，明确提示不适用的目标/工作/完成说明/条件将被清除，有已填写内容时确认后切换。

Adjust 初次可带入原行动目标及工作，用户仍需填写理由和明确选择引用。不存在可引用来源时说明原因，禁止保存 Adjust / New；Observe 缺少实施记录时禁用并解释。

界面和服务约束一致：总决定最多六项，新增最多三项，所有非 Defer 决定合计最多三项，包含 Observe。不得自动截断。理由、完成说明、重考虑条件各最多 1,200 字符，目标 2,000，工作 4,000，引用最多 12 个且唯一。计数以与后端一致的 Unicode 字符语义处理，另校验总 UTF-8 字节上限。

### 4.5 响应式及无障碍

宽屏保持三列；中等宽度行动导航改为顶部横向列表，证据与编辑仍并排；窄屏按行动导航、证据、编辑依次排版，提供跳转到编辑/证据的页内链接。不叠加多个内部滚动区。

导航在可用高度足够时跟随滚动，不能遮挡焦点或底部内容。表单字段有标签和关联错误；错误摘要聚焦到首个无效字段；确认对话框有焦点限制和返回焦点；键盘可操作所有选项及历史分页，选中状态不只靠颜色。状态变化适度使用 live region，尊重减少动画设置。

## 5. 保存、只读历史与并发

### 5.1 正常保存

1. 编辑期间只更新本页内存，不自动保存，不自动生成报告。
2. `Review & save` 校验完整已选择决定，并展示每项类型、理由、条件、工作变更及来源；明确列出未决定的原行动。
3. 允许部分决定或空列表，确认文案须明确本版本会保留哪些决定、哪些清空。清空最新版本不是删除历史。
4. 用户确认后生成一次请求 ID，冻结本次请求和前版 ID/checksum，提交期间禁止重复提交和改变请求内容。
5. 仅收到并校验精确绑定的保存回执后显示成功；展示新版本的只读内容、原报告未改变、未扣点。

### 5.2 历史

历史目录每页最多 20 条，按版本倒序，以 `Load older versions` 加载，显示版本号、时间、决定数量。私人理由只在选择并成功读取具体版本后展示。

历史永远只读。`Edit a new version` 重新读取最新头和该版本，核实后复制到草稿。即便正查看旧版，也从最新头开始，不提供将旧版直接回滚或自动覆盖最新版本的功能。编辑期间切历史保留当前内存草稿；返回 `Your decisions` 恢复该草稿，不重新初始化。

### 5.3 冲突及结果未知

- 确定的字段错误：保留草稿，定位错误。
- `STALE`：保留草稿，提示已有更新版本，提供“查看最新”和“从最新版重新编辑”；不自动合并、不自动续发新 ID。用户明确放弃本地草稿后才换基线。
- `CONFLICT`：说明请求恢复信息不一致，停止重复提交，允许核实已有版本；不盲目换 ID 掩盖冲突。
- 超时、网络断开或不合法的成功回执：显示结果未知。在当前页面用原 ID 精确读回或以完全相同请求恢复；不自动发新 ID。
- 明确无权限、Case 不活跃或身份切换：清除敏感事实和草稿，停止恢复，不暴露其他用户记录是否存在。
- 历史/来源临时不可用：显示读取失败和重试，不降级成空历史或空依据。

## 6. 草稿与刷新恢复边界

私人理由、工作、完成说明和来源详情只保存在内存，不写入 localStorage / sessionStorage、URL、日志或分析事件。离开页面或用最新版本替换非空未保存草稿前给出确认；刷新/关闭使用浏览器原生未保存提示。不承诺浏览器崩溃后恢复未保存文本。

发送前可向 sessionStorage 写入最小待核实标记：owner / Case / report / review / request ID，不含决定正文、理由或来源。标记按身份命名、严格校验，只有解析出可信绑定后才用于精确读回；存储不可用时仍允许保存，但提示刷新后不具备自动核实入口。

刷新发现标记时先核实同 ID 记录，不自动提交。确认已保存则显示回执并清理标记；若确定查询不到，不把未知请求断言为已取消，允许再次核实及手动查看历史。需要离开恢复状态并开始新草稿时必须明确提示：旧请求仍可能完成；任何后续保存仍受最新前版检查保护。不会以一次未查询到代替对先前事务结果的确认。

## 7. 真实数据与模块边界

复用第四批 `ReviewDecisionService`、不可变表及三个 RPC；不复制保存规则，不新增可改写历史的入口。

新增后端展示上下文服务，读取精确冻结包并投影：只读 WorkspaceView、原批准行动的完整目标/工作、与行动绑定的允许引用目录，以及报告/快照身份校验值。不得把完整底层 bundle、供应商原始载荷或未选中来源发给浏览器。上下文与决定头分开读取，客户端交叉验证绑定，保存仍以数据库前版检查为最终保证。

新增内部 `/api/v2/review-decisions`，操作为 context / history / read / save；仅内部凭据调用，注入并校验可信身份。新增浏览器 BFF `/api/v2/cases/[id]/reports/[reportId]/review-decisions`：GET 仅允许 context / history / read，POST 仅允许 save。

浏览器不得提供可信 owner / Case / report 字段；BFF 从会话和路径注入。save 携带已有 SaveDecision 结构，read / history 明确 review ID。未知字段、重复 JSON 键、重复查询参数、非有限数值、非法游标或 UUID 必须拒绝。

原 SaveDecision 正文仍限 64 KiB；外层身份与操作封套限 72 KiB。新展示上下文响应限 512 KiB，决定回执限 128 KiB，历史目录限 32 KiB，错误正文限 2 KiB；超过上限拒绝，不截断。传输私有不缓存、禁止重定向、有界读取、30 秒超时；写入检查同源、Origin、Host、Sec-Fetch-Site 及 Content-Type。

错误只返回安全代码与产品文案，不回显原始 SQL、供应商错误或私人正文。后端验证归属、证据及完整版本校验值；BFF/浏览器严格验证 schema、预期操作和身份/快照/版本绑定。

前端分离：页面协调器、行动导航、决定表单、只读证据、保存确认、历史列表/内容、草稿与恢复状态、请求与契约校验。优先复用 EvidenceFacts，不继续把全部状态塞入已有 ReviewWorkspace 大组件。

新增默认关闭的 `V22_REVIEW_DECISIONS_WORKSPACE_ENABLED`，前后端均依赖既有复核工作区及能力开关。本批仅增加定义与测试，不修改真实环境值。关闭时新页面/入口/API 不可用，既有证据查看和存储不受影响。

## 8. 零行动与限制状态

没有原行动时保留诊断及限制，显示“当前快照没有可记录决定的行动”，不得补造三条行动。来源目录为空则禁用新增，允许明确保存空决定版本。保存空版不代表诊断失败或退款，也不产生报告。

没有数据、没有实施记录、没有决定历史、读取失败分别是不同状态。所有限制来自固定快照；选择 Observe 不会把 SEO 完成说明升级成系统验证，也不会把趋势变化升级为因果结论。
