# P2 接续设计：服务证据、工作包与批准 PDF

日期：2026-10-20。依据：已批准主计划 §7、前批设计，以及用户“继续构建”授权。属于既有方案的实现拆分，不新增收费产品、不发布新入口、不自动提交。

## 1. 服务分析输入

保留旧 FirstPartyFindingsInput / CrossSourceFindingsInput 的父报告必填约束，抽出已经验证的纯规则核心供新入口复用。新增内部 ServiceFirstPartyInput、ServiceCrossSourceInput，父报告允许明确为 null；不以当前任务编号或虚构 Prospect 冒充历史。

CapabilityServiceInput 包含当前公开检查输入和第一方检查输入；完整生成输入摘要绑定身份、查询、来源和限制。manifest.mode 为 first_service 时不能提供历史；after_acquisition 必须核对冻结前版的完整摘要、Case、ID、类型与版本。review 不在本轮开放。

GSC、GA4 仍须匹配、健康、有效且绑定到同一 Case 和授权来源；源数据摘要、资源、日期范围由原规则再次检查，跨来源继续检查域名、页面身份和可比窗口。官方 GBP Performance 可选，保持既有精确值/原文不进入长期结果的保留政策。

## 2. 实际规则到报告

当前公开规则、单源规则与跨源规则执行后再组装新报告。保留实际观察、数值、对象、时间和期间；冲突作为冲突展示，事件不是合格询盘，增长不自动转换成工作建议。

当没有行动时，保留公开诊断及实际 GSC/GA4 检查总量，说明范围与未解决检查，而非输出空报告或“SEO 健康”结论。正常完成策略仍为一点、不返还；生成函数自身不消费或返还点数。

行动最多三项，现阶段沿用证据/严重度/置信度和依赖排序，技术访问与测量前置，不宣称已经实现 P4 业务价值评分。同一页面的相同检查合并；复用已有页面归一化规则合并追踪参数、主机别名和协议差异，但原始来源值不改写。`(not set)` 不能作为真实页面去修改；相关工作来自具体测量检查。

## 3. 材料与检查点

服务材料包括测量范围/事件检查、现有服务页编辑 brief、查询与页面匹配检查。页面表现不能单独证明缺少某段文案，因此业务内容保持待确认，不能把未知事实写为可发布成稿。材料与报告一起确定性生成，无额外模型调用或隐式收费重写。

服务检查点仅保存最终报告和校验值，不保存临时官方 GBP 原文。按原任务、冻结输入和真实前版摘要重放；损坏 JSON、错任务、变更前版均不得被作为成功结果交付。

## 4. 批准版本与 PDF

新增统一批准交付结构，来源必须是已持久化、归属匹配、摘要正确、状态 approved 的完整修订。最新草稿不能回退到旧批准版来生成“新交付”；旧分享的后续接入按固定修订 ID 读取，查不到不得跳到最新版本。

PDF 渲染同一批准投影，不重新编写结论或材料；动态 0–3 行动，保留证据、执行材料、待确认项、SEO 说明、版本和限制。复用产品现有 React PDF 及临时品牌能力，仅允许内嵌 PNG/JPEG Logo，不抓取远程图片。

当前 PDF 字体沿用 Helvetica，支持范围外的文字明确失败，不静默丢字；多语言字体覆盖是挂载新出口前需补齐的限制。生成、文字提取、页面边界和视觉检查作为本批验收，不把本地渲染器当成已接通真实下载 API。

## 5. 挂载边界

本批不修改现有收费 API、worker 选择、成功回调或下载/分享端点，不新建迁移。新结果仍是候选报告；接下来必须完成报告落库、任务成功和账本消费的原子互斥，再挂实际报告页、保存、PDF/分享，最后完成 P2 整阶段验收。
