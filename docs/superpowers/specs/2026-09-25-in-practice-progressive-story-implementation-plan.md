# In Practice 渐进式场景故事实施计划

## 目标

把 `/use-cases` 从六张割裂的大卡片重构为六段连续的纵向工作故事，并落实 2026-09-24 已确认的设计规格。

## 实施步骤

### 1. 内容模型与页面骨架

- 将六个场景的数据从 `UseCasesV22.tsx` 移到独立数据文件。
- 为每个场景补齐统一叙事字段：现实情境、问题、问题本质、分析、处理方式、工作决定、三个交付结果、SEO 最终判断和下一场景过渡。
- 保留现有可信度边界，不增加虚构数据和不存在的产品能力。

### 2. 六个语义证据视觉

- 场景 1：公开证据汇入第一轮工作决定。
- 场景 2：完善现有页、继续核查或新增页面的判断路径。
- 场景 3：网站、公开商家资料和客户确认信息的字段级对照。
- 场景 4：查询到页面、站内体验和关键事件的分析路径。
- 场景 5：带推荐理由的前三项优先行动。
- 场景 6：计划、实施、复查和下一决定的状态时间线。

### 3. 视觉系统

- 建立页面独立 CSS Module，集中管理颜色、间距、排版、响应式和动效。
- 移除等高双栏、嵌套描边卡片和场景之间的装饰性横线。
- 使用暖白、浅薄荷绿、深绿墨色与有限品牌绿建立层次。
- 每个场景只保留一个深色工作决定作为视觉峰值。

### 4. 导航与交互

- 增加桌面端粘性场景导航和当前章节状态。
- 增加移动端当前场景入口与可展开的全部场景目录。
- 使用 IntersectionObserver 同步当前章节，并尊重 reduced-motion。
- 统一箭头语义：向下箭头仅滚动，向右箭头仅页面跳转。

### 5. 验证

- 添加组件测试，验证六个场景、导航入口、主要决定和可信度说明。
- 运行 TypeScript 检查、相关 Vitest 测试和生产构建。
- 使用 Playwright 检查 390px、768px、1440px 三档布局、锚点跳转、移动目录、横向溢出和浏览器控制台。

## 完成标准

- 单个场景可独立读出“问题 → 本质 → 分析 → 处理 → 结果”。
- 六个场景不再依赖同一张通用卡片模板。
- 没有因等高布局产生的大面积空白。
- 390px、768px、1440px 无页面级横向溢出。
- 键盘导航、焦点样式、当前章节状态和 reduced-motion 可用。
- 类型检查、相关测试与生产构建通过。
