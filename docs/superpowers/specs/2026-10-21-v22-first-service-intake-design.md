# 首次服务启动基础（P3 首批）

沿用已批准执行文档 §4.1、§8；不改变产品流程或计费决策。本批不开放页面、不新增外部收费 API。

## 选择

不移除旧 Verified 的父报告校验，也不创建虚构 Prospect。新增独立、仅服务端可调用的首次服务准备记录，复用统一任务、账本、输入清单及新版报告结算。后续采集协调器和页面复用这一边界。相较另建整套收费系统，这保留统一幂等/技术失败补偿；相较直接置空 parent，这保留来源和业务身份检查。

## 事务与输入

调用者提供 owner、Case、job、幂等键、已保存业务版本和明确选定的 GSC/GA4 快照 ID。首次调用要求无已完成报告、无其他有效工作流；业务版本为当前确认版本，竞品 1–3 个、业务重点可空，公开 GBP URL 已提供。数据库核验选中快照是当前资源最新快照，身份、授权范围、健康、时效、覆盖及资源 ID 匹配；未就绪不扣点。授权锁先于 Case 锁，锁后重验资源集合。

一次事务扣统一余额 1 点、创建 verified_report 任务、verified_debit 账本及不可变准备记录。固定业务身份、业务版本、私有来源引用和原始 20 分钟截止时间；不生成 Prospect、不产生旧版收费记录。相同请求重放返回同一任务，包括失败或成功终态，不重新扣点、不重新挑最新快照；不同请求不可冒用同一幂等键。新首次服务请求不能越过既有任务或已完成报告。

公开页面/搜索/竞品/GBP 实际采集与最终来源就绪仍在该已付费工作流内进行。准备记录不是完整分析输入，也不能直接生成报告。后续冻结清单必须是 first_service、无历史，使用已固定业务及 GSC/GA4；公开来源仍由已有完整准备函数核验。新记录不得落入旧报告链。既有恢复任务同时处理没有 manifest 的首次服务超时，补偿只发生一次。

## 本批交付与后续

交付增量迁移、内部 TypeScript 启动仓储、隔离数据库回归及记录。测试含无 Prospect、拒绝过期/错误身份/缺授权/旧快照、并发式重放、零余额、故障回滚、冻结输入偷换、零行动消费及迟到失败互斥。

本批不接页面或真实采集队列；下一批是首次服务采集/准备协调器及状态恢复，再接 Case 创建/选择、连接中心和显式“使用 1 点”按钮。所有生产开关保留原值，远程迁移与部署未授权。
