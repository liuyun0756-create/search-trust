# 交给实施者的使用说明

## 给 Codex 的开场指令（可直接复制）

```
按 docs/acquisition-plan/PLAN.md 执行任务 <任务ID>。

规则：
1. 只做这一个任务，不要顺手改其他文件或重构。
2. 遵守 PLAN.md 第 1.2 节的全局规则，特别是"没抓到不能当成没有"和"不动已冻结证据"。
3. 完成后按 PLAN.md 第 1.3 节的模板写 docs/acquisition-plan/reviews/<任务ID>.md。
4. 自测命令必须真的执行并把结果写进交付说明。不要声称跑过没跑过的测试。
5. 遇到 PLAN.md 没覆盖的决策，停下来写进"待决问题"，不要自己定。
6. 不要提交部署，不要动 git 里已有的未提交文件（docs/superpowers/plans/ 下的验收记录）。
```

## 给验收人的指令

```
验收 <任务ID>。对照 PLAN.md 中该任务的验收标准逐条核对：

1. 读 reviews/<任务ID>.md，看"待决问题"是否需要我先拍板。
2. 自己跑一遍自测命令，不只看交付说明里的结果。
3. 逐条核对验收标准，特别检查全局规则第 3 条（没抓到不能当成没有）
   和第 4 条（客户可见文字不含内部信息）。
4. 用真实样本或夹具复现"改动前后对比"，确认改动确实生效。
5. 结论写进 reviews/<任务ID>.md 的"验收"部分，并更新 PLAN.md 第四节状态表。
```

## 任务之间的依赖

```
P0-06 ──> P0-07
P0-03 ──> P0-04（Firecrawl 页面抓取兜底要复用联系信息识别逻辑）
P1-02 ──> P1-04（要先有对比数据才能写"为什么"）
```

其余 P0 任务相互独立，可以按顺序推进。P2 可以在 P1 后半段并行开始。
