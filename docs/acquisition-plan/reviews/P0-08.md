## 实现说明

1. `eval_gold.py` 校验输入文件 SHA-256 后调用真实的 `build_public_capability_report` 和 `build_public_findings`。Nova 先按原规则重放，确认规范 JSON 字节与冻结 v5 一致，再仅在内存中派生当前 v8 输入。没有修改生产代码、合约、旧规则或冻结文件。
2. 发现比对按完整 `rule_id + RuleTarget` 进行，区分 URL、查询词和采样条件；重复标注拒绝评估。每个生成发现输出正确、误报或无法判断；人工期望触发而实际已检查未触发的项目输出漏报。未检查、未实现、无匹配检查和未标注不冒充通过或漏报。
3. 误报率＝误报数÷可判定的已生成发现数。未检查率＝人工确认存在且系统判未检查的字段数÷人工确认存在的字段数，并复用实际 `identity_unresolved`、`site_content_not_checked` 等原因。空分母显示 null。整站缺输入时不虚构系统字段状态，覆盖不全的比率也显示 null，另列不可评估的存在字段数。
4. 人工 NAP/GBP、经营模式、本地实体、信任声明和链接目标均为空。具体期待由负责人核对后填写；不会把网页电话当作 GBP 值或把反馈描述当成已证实事实。当前未实现的类别、营业时间对齐、信任链接、本地内容判断保留为无法判断。
