## 实现说明

1. 自动识别与有效模式分离。确认必须匹配商家域名、所选分支、来源集合摘要；旧预检自动模式不视为人工确认。正向上门描述只建议 service_area，并保留 hybrid 备选；公开地址、服务区标签和行业词不能证明接待门店。GBP 只有 observed 的真布尔 true 才作为依据，false/null/未返回不证明 storefront。隐藏、未闭合、第三方、否定、无法读取及超限片段不能建立正向模式；跨页面到访/上门归属未解决、分支提示或冲突均需确认。
2. `operating_location` 保存 GBP 原文及来源位置，地址用途默认 unknown；缺地址时 location=null，不用城市采样点回填。`target_market` 单独绑定原采样上下文。Vision-Tech 保留 Llanelli 地址、Swansea 市场；Volcanoes 保留 Keaau 地址、Hilo 市场，未把 GBP 地址叫作集合点。没有可靠分解依据的 city/region/postal_code 仍为空。
3. service_area/meeting_point 的地址为 not_applicable；模式 null 为 not_checked / operating_model_unresolved。storefront/hybrid 仍须明确分支和接待用途，条件不足为 not_checked / operating_location_unresolved；其他既有抓取/实体/来源资格不放宽。新类型缺可靠国家时不猜电话/地址比较。未检查不能变成缺失。文本和渲染仍只能确认一致。
4. findings → 行动候选 → 材料正常重建。真实 Vision-Tech/Volcanoes 未产生地址候选或材料；另外用结构化地址确实不一致的合成样本验证：storefront 时存在地址 finding、候选和材料，换成 service_area/meeting_point 后三者一起消失，冻结来源不变。
5. 首次服务兼容保留完整 v2 身份在 Case；三个旧模式映射值不变，旧请求的 primary_location 延续旧服务中“目标市场”的含义。兼容投影不写回 Case。数据库从读取、预留到 worker 绑定/后续准备都使用同一投影；meeting_point/null 专门提示 `First-service analysis is not yet supported for a meeting-point or unconfirmed operating model.`。旧 Case 原形状和历史三值路径保留。
6. 本段提供显式 v13 输入与离线预览，**不切换默认获客版本**（仍 v12）；新预检/GBP 查找接入和 SEO 重判持久化属于第二、三段。当前 v3 acquisition 的 evidence_as_of 等于原 evaluated_at；离线回放保留原分析时点，未把今日确认伪装成新采集，也未向数据库保存新判定。append-only 身份表、public_reassessment/new report ID/时间拆分持久化在第三段实现；本轮没有冒用旧 job ID 写入旧报告。

### 实现说明

1. **先缓存**：`build_identity_gbp_lookup(settings)` 构造新入口，`lookup(GbpIdentityRequest, ledger=...)` 接收由服务端加载、归属本 Case 的保存记录。检查全部候选，按来源/记录 ID/哈希去重；已有明确分支确认且 D/P 通过时优先复用。相同 place_id 与 CID 的显式关系可去重，不按名称合并不同 CID。多个合格分支没有明确选择时输出 `identity_unconfirmed / multiple_verified_branches`，不继续付费猜选。
2. **再链接、域名/电话，最后名称**：只解析提供的 Google URL 或已经保存的短链终点，不做新的短链 HTTP 请求。缓存不足才排队补详情、刷新过期匹配线索、查“域名 + 已观察电话 + 市场/国家”，最后查页面真实品牌或有来源的 SEO 名称。缺市场快照时返回 `awaiting_market_cache`，不额外购买市场查询；原市场阶段完成后可再次传入缓存定位商家。没有真实名称就不从域名编造一个名称查询。
3. **D/P 硬门槛**：域名做大小写、IDNA、末尾点和 www 归一；主机精确比较，不模糊匹配，也不把同注册域下不同租户合并。别名必须来自已有跳转或 SEO 确认记录。电话使用已有 `compare_phones` 和可靠经营国家；只接受同站、归属本商家的观察。缺失/无法解析为 unknown，不当作一致或明确不一致。D 或 P 为 true 才能入选，另一项冲突仍保留。名称、相近地址、用户链接和用户选 CID 都不能绕过门槛。
4. **归属与非循环证据**：`observations_from_site_selection` 复用现有页面抽取/实体资格选择，只传 eligible 的名称/电话；排除需要已匹配 GBP 才成立的 text_pattern，避免先用 GBP 证明电话、再用电话证明 GBP 的循环。脚本、外部实体、竞品、隐私/评论号码不进入匹配。Seamless 的旧正则扫描还抓到了脚本 `et_link_options_data` 中的 `8504557246`；它不能作为本商家可见号码。测试明确标为非归属，并用现有抽取器证明脚本/外部实体不会进入新桥接结果。
5. **未检查与未找到分开**：停用、等待市场、请求错误、超时、格式不完整、额度不足均为未完成，不下“现实中没有 GBP”结论。只有有效查询流程完成且无正向匹配才给 `gbp_not_found / no_verified_domain_or_phone_match`；逐候选保留缺字段/冲突原因。地址占位给 `identity_unconfirmed / address_only_place`，同时保留 `lookup_stop_reason`，不会用街道文字充当商家名称。
6. **时效不重写**：缓存保留原观察时间、有效期和可用性。过期/不可用记录仅作线索；详情刷新是新观察，需占用额外请求。本段真实市场回放使用原采集当天的评估时点和原一日有效期，不声称这些市场样本今天仍新鲜。没有声明过期时间的旧 lookup 摘录保留该缺省，不新造时间。
7. **最多三次实际额外请求**：复用现有 SerpAPI provider，在每次 HTTP 请求之前记账，密钥切换重试、补详情、名称搜索共用 3 次总额。关闭开关时连 provider 都不创建。相同实例同一 Case/域名的调用串行并继承台账，不能用旧台账清零；跨实例恢复须传回已保存台账（测试覆盖）。正式入口/持久化接线属于第三段，恢复时须保留本段返回的台账，不能为每次重试新建空台账。错误文字不携带 provider 异常或密钥。
8. **竞品边界**：过滤已经排序/入选的竞品池，排除客户 CID/place_id 和规范域名，最多保留 3 家；不为了凑三家编造或额外搜索竞品。

### 实现说明与边界

1. 审核页报告上方的 **Identity confirmation** 将经营模式、Google Business Profile 分支和理由放在同一区域。未确认时明确显示 `Identity is not confirmed. Address check is temporarily unavailable.`；改选后提示尚未应用。预览展示地址前后结果、候选增减及失效文案影响，保存失败或并发冲突保留选择。
2. 正式路径是登录用户 BFF → 内部鉴权 API → Case/owner 绑定 RPC → 已保存的 generation recipe 和来源。第二段的缓存 → 链接/域名电话 → 名称查找已在此正式身份审核入口调用。默认获客 v12 预检不改；没有宣称已整体切换获客入口。
3. `workspace`、`preview`、`commit` 不调用 provider。只有显式 `lookup` 且默认关闭的 `V22_IDENTITY_GBP_INCREMENTAL_ENABLED` 被打开，才可能产生新增请求。未抓到、失败、来源过期或分支未确认不转成缺失/不一致。
4. `case_business_identity_versions`、重判请求、完成凭据和查找结果 append-only。查找台账按 **Case + 规范域名** 校验并持久化；不同报告共用累计三次限额。数据库 Case 锁与预占递增检查防止并发重复预占；保留 started 的中断请求也消耗一次，避免重复计费。
5. 离线预览产生新的 report/manifest/identity ID、checksum 和 `base_report_ref`。`evidence_as_of` 继承原分析时点，`evaluated_at` 和确认时间是本次重判时间；来源本身及其 fetched/expires/checksum 不变。与**实际基础报告**比较无关事实，无法解释的变化返回停止，不通过中间规则升级回放掩盖差异。
6. `public_reassessment` 免采集额度完成路径必须有持久请求/完成凭据，不能只改 settlement 字符串绕过付费报告门禁。新报告不复制原 delivery revision，不按位置套用旧文案，必须重新审核批准才可分享/PDF；原报告、已批准修订及分享指向保持不变。
7. 新首次服务读取最新确认身份并映射旧三值；`storefront/service_area/hybrid` 保留目标市场，`meeting_point/null` 明确暂不支持。身份提交与 Case 活动任务冲突时拒绝，防止改变执行中的输入。原 Case 行、旧请求和冻结身份不 UPDATE。
8. **GBP 分支资料边界**：D/P 匹配的候选不等于完整 GBP 详情。Volcanoes 两个 CID 都出现在同一个选择区，完整冻结输入绑定的 `16906567364961418758` 可用于离线重判；另一个 `17234196230790564629` 没有本轮完整冻结详情，显示 `saved details required`，不能把它的名称搜索记录伪装成完整详情。没有付费补采或猜分支。
9. 本地预览的报告/事实生成走真实 Python 服务，保存/批准是 stub；真实数据库语义由 PGlite 测试单独验证。没有把本地截图说成线上或生产库验收。
