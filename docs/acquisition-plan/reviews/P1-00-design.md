# P1-00 设计说明（已批准实施，2026-11-04）

范围：仅修复已确认的 10 条误报；方案已获文末设计确认及多城市补充裁定，实施结果见 `P1-00.md` 最终交付说明。依据 PLAN 的 P1-00、全局规则及 `P0-09-annotation.md`。基线为误报 **10/43 = 23.3%**、字段未检查 **9/26 = 34.6%**；不改六站 truth、冻结输入或历史证据。

## 1. CMS 后台与登录页

- 新采集在候选入队、深页选择时排除：URL 解码一次后，路径段为 `wp-login.php`、`wp-admin`，或解析出的查询参数名为 `action`（包含空值，大小写归一）。按路径段/参数名匹配，不误伤 `transaction`、`/action-plans/` 或正文中提到登录的普通页面；不凭标题含 “login” 就排除。
- 冻结输入离线重放时不删页面：对请求 URL、最终 URL 任一命中的页面，noindex 记 `not_checked/page_out_of_scope`，且不加入重复标题分组、不算作“缺标题”。正常页面仍按原规则判断。保存排除理由与 URL 证据，避免变成“已检查且没有问题”。已有 HTTP 观察不改（HTTP 扩展属于 P1-07）。
- 此策略只用于新规则集的获客采集/判定，新的采样缓存命名空间与 v9 隔离；旧缓存、旧执行器原样保留。若用户指定的唯一目标也是后台页，则明确记录范围不适用，不换成猜测的目标页。

## 2. 自然样本是否本地化（已确认，并纳入多城市裁定）

**输入与边界。** 按同一查询、同一 organic 样本单独判断；不使用 Maps 的本地结果替 organic 背书。只读已保存的 `target_market.city/region/country_code` 与各结果的 `address/display_name/snippet/url`。源码确认结果 `latitude/longitude/country_code` 来自请求采样点，不能用作结果经营所在地。无地理编码、LLM、实时抓取或按域名猜所在地。

**单条结果三态：local / non_local / unknown。** 用可审计的固定规则提取“页面面向哪里”的信息：

1. 采用明确的地址城市/地区；或标题中的 `in/near <城市>, <州>`、`<城市>, <州>`、`<城市> <州全名>` 等地点片段；或 URL 的明确地点参数（如 `find_loc`）和带州/城市层级的路径。美国州缩写/全名使用固定完整映射，不建立为六站定制的外地城市名单；英文其他市场只接受可明确解析的城市/地区，不强行套用美国地址规则。
2. 标题/摘要完整词匹配目标城市，且没有冲突地点，可记 local。明确地点与目标城市、州/国家不符可记 non_local；只有州相同、全国目录、没有地点、只有品牌或域名中含疑似地名，一律 unknown。摘要里的外地词单独出现不够，必须有明确地址或服务地点句式；`Alaska Solutions` 不能因为含 Alaska 就算外地。多城市只有在每个地点都明确带州/国家、且全部不同于目标市场的州/国家时才记 non_local；含无州地点（如 Wichita）、本州地点、目标城市或其他冲突时仍记 unknown。城市重名而地区不足也记 unknown；公司/品牌中的地名不作为地点。此项按文末裁定补充，阈值和分母不变。
3. 城市按输入的城市范围理解，不自行扩展到周边城市/都会区；县、泛化区域与城市之间无法直接比较时记 unknown。单条诊断记录采用的字段路径、地点片段及三态，能够回到原快照核查。

**样本阈值。** 同一 organic 样本按规范 URL 去重，每个 URL 一票；无 URL 的结果仍计入分母、记 unknown，同 URL 有冲突也记 unknown。令总数 N、明确外地数 O、本地数 L：至少 3 条且 **O > N/2** 才认定“明确外地结果占多数”；不是按“能识别地点的结果”作分母。正好一半、样本不足、没有出现目标城市都不能直接认定外地。

**对规则的影响。** 仅当原本满足检查条件、客户域名未出现且满足上述外地多数条件时，将 `market_site_domain_unobserved` 改为 `not_checked/sample_not_local`，不产生发现或缺失行动。其余情况保留原相关性、身份和域名观察逻辑；unknown 不标成“已证实本地”，也不因地理识别失败新增结论。Maps/local_pack、客户已出现时的结果、竞品排名规则本任务不改。客户说明按最终验收修订为英文：“This organic search sample mostly reflected other areas, so it is not used to judge local visibility.”，不显示内部原因码或采样参数。

**真实样本复核（以多城市裁定及最终离线输出为准）。** PR/All Star 各 N=10、O=6、L=1、unknown=3；Napa、Santa Clara、San Diego、Idaho、Sioux Falls、Kansas City 为外地，Sonoma County 为 unknown，Hutchinson/无州 Wichita 的多城市结果也为 unknown。Seamless 为 N=8、O=6、L=0、unknown=2，其中 Helena/East Birmingham 都明确为 AL、Raceland/Westwego 都明确为 LA，因此按补充裁定记 non_local。初稿仅看标题/URL 的估计已被完整片段复核替代，实际逐条审计见 `P1-00.md`。

## 3. 商家名称归一化

仅在原身份与候选资格校验通过后启用新名称比较器：NFKC、大小写/空白归一、标点与连字符转词边界、`&/and` 等价；删除末尾完整法律后缀 LLC/Inc/Incorporated/Corp/Corporation/Ltd/Limited（含点号形式），并删除首尾与明确目标城市完整词序列一致的城市修饰。后缀与城市可交替去除，必须保留非空品牌核心；城市删除后少于两个词时不应用城市放宽。不得删除内部品牌词、任意地名或业务词，也不做编辑距离/子串/LLM 模糊匹配。

归一后完全相等才记 semantic_match；其余仍走原比较，缺值或身份不明确继续 not_checked。预期 `All Star Plumbing / All Star Plumbing Fresno`、`Vision-Tech AV / Vision Tech AV LTD` 一致；`Seamless Gutters of Pensacola / Gutter Solutions & Home Improvements` 仍不一致。原值、转换步骤与新比较器版本均可追溯，不修改 GBP/网站原文。

## 设计确认（2026-11-04，验收人：Claude）：批准实施，附 5 条条件

整体方案批准：第 1 节按路径段和参数名排除；第 2 节用明确地点三态、全样本作分母、至少 3 条且严格过半；第 3 节只去掉首尾的城市修饰词和末尾的法律后缀。新规则集定为 v10，v9 基线断言保留。

条件：
1. **地点判定要能逐条审计。** 交付说明里给出 3 个 near-me 样本（PR / All Star 共用 1 个、Seamless 1 个）每条结果的三态、采用的字段和片段，以及 N/O/L。另外要列出**所有仍然触发**的 `market_site_domain_unobserved` 样本的 N/O/L，证明本地样本没有被误判为 not_checked。按我的核对，PR 的 near-me 样本外地结果约 6–7 条，刚过半数线。如果实际 O ≤ N/2，照实写出来并停下，不放宽阈值。
2. **迁移**：新增 v10 的数据库迁移，排在 `20261104100000` 之后，沿用 P0-10 的写法（目标缺失就 raise），站点库存 v2 只允许 v9/v10。P0 上线清单（PLAN 第六节）的迁移列表同步追加。
3. **预期结果写清分子分母变化**：10 条误报不应再以“发现”形式出现。near-me 的 3 条会变成“无法判断（not_checked）”，名称的 2 条会变成“正确（未触发）”，登录页的 5 条会变成“排除/无法判断”。可判定发现预计从 43 降到 33。不要只报一个误报率百分比。
4. **客户文案**：只用设计里那一句；报告和导出里都不能出现 `sample_not_local`、`page_out_of_scope` 或采样坐标。
5. 范围不扩大：category/tag 重复标题是已确认的正确发现，保持不变；`/wp-json/`、`xmlrpc.php` 等其他后台路径这次不加，需要的话记为观察项。


**补充（2026-11-04，验收人裁定）：** 多地点结果只有在每个地点都带明确的州或国家、并且全部不同于目标市场的州或国家时，才记 non_local。只要有一个地点没有州、或和目标市场同州、或就是目标城市，就记 unknown。阈值不变。详见 P1-00.md 中的裁定。
