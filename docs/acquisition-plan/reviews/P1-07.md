## 实现说明

### 排序与冻结候选

只在 `v22_capability_public_v12` 使用报告 `2.2.7`、`v22_business_priority_v3`。技术优先必须由**同一条** HTTP/noindex 发现满足 fact、confirmed、medium/high、supported、有证据；不能借行动内其他强依据提权。已保存且 checked 的 HTTP 4xx/5xx、合格 HTML 的显式 noindex 可以提权；超时/无状态码不可以。后台/登录页判断复用 P1-00，未改动。

排序遵守显式依赖；在可排序集合中，全弱候选排后且不进入默认客户行动，合格技术行动优先，其余仍按原业务匹配/证据/严重度/置信度/执行条件/稳定 ID。混合搜索依据沿用 P0-07，不因含一条弱依据就全部排除。强候选若依赖未选的弱候选，也不补入客户组合，原因明确为 `dependency_not_selected`。客户最终不补凑行动。

`action_candidates` 保存完整行动（步骤、材料、finding/evidence 关系），包含系统入选与未选；`candidate_order` 保存完整顺序，各决策记录 `technical_finding_ids`、`default_visible`。`actions` 最多 3 条且必须逐项等于池内原件。候选上限 1000、原报告 2 MB 上限不变，超限报错，不截断或静默丢弃；冻结证据仍保持原样。

### 技术前置是警告确认，依赖仍是硬约束

`v22_delivery_revision_v3` 从同一报告冻结候选池选取等量槽位：0/1/2/3 条只能保存原数量，不能追加、删除或重复；保留 source checksum、报告/用户/Case 绑定，材料只允许原有 title/body 编辑，不能移植另一行动的材料或改证据。

**技术优先不再是交付层级硬限制**：独立技术行动可被调到后面；替掉最后一条技术行动（或从客户可见子集隐藏全部技术行动）时，服务端要求如下确认记录，确认后允许保存。第一段提供校验及记录契约，弹窗由第二段实现，当前未做弹窗。

```json
{
  "technical_omission_confirmation": {
    "confirmed": true,
    "omitted_action_ids": ["ac-synthetic-0"],
    "selected_action_ids": ["ac-synthetic-4", "ac-synthetic-1", "ac-synthetic-2"],
    "client_action_ids": ["ac-synthetic-4", "ac-synthetic-1", "ac-synthetic-2"]
  }
}
```

只接受真正 JSON `true`。省略、伪造、过时的选择/可见列表，或已恢复技术行动却携带旧确认记录，均拒绝。记录随用户绑定的不可变修订保存，保存时间和批准状态沿用现有数据库字段。此处拒绝的是**未确认的保存**，不是禁止 SEO 替换。

无论是否确认，都硬性验证选中及客户可见子集的依赖闭合和先后顺序；不自动追加依赖。未知/跨报告 ID、重复、材料证据篡改、错误 checksum、过期 expected_revision 均拒绝。恢复原组合后去掉遗漏确认即可保存新修订；历史修订与冻结报告不变。弱候选替入时可保存为仅顾问可见，SEO 显式选择后也可交付，继承 P0-07 编辑权；不因此获得技术优先资格。

## 观察项：Seamless 名称不一致为什么是 low

负责人已确认 “Seamless Gutters of Pensacola” 与 “Gutter Solutions & Home Improvements” 的名称不一致应报告，事实判断保留，金标准仍计为正确发现。当前 low 有两层代码来源：

### 实现说明

“其他候选”位于已入选卡片之后、审核确认之前，按完整候选顺序显示。每条给出目标、依据状态、置信度、排序理由，可以展开步骤和材料。替换必须选择已有槽位，再看前后对照；没有追加操作。退出行动回到候选区，会话内再次选回时恢复自己的编辑。恢复系统顺序只排序当前组合；恢复系统选择另走对照确认，且保留当前及缓存的文案。

移除最后一条客户可见技术行动会警告；确认后记录与所选顺序、客户可见子集完全一致的 `technical_omission_confirmation`。组合或顺序变化后不能沿用过时确认；恢复技术行动则移除确认。显式依赖不满足时禁用替换或拒绝隐藏，不会自动追加前置行动。保存沿用正式接口的绑定、材料身份和 expected_revision 校验，替换会清除批准勾选。

全弱候选显示 `Advisor only · verification needed`（仅顾问可见，需核实），换入后默认不勾选客户交付；SEO 明确勾选并重新批准后可以交付，原置信度不提高。Seamless 继续方案 A：名称规则上限 low，不修改事实或金标准；真实样本验证名称修正从候选区换入后仍保持 **2 个槽位**，明确勾选后可交付。

网页、分享和 PDF 均从批准修订的客户子集投影，仅显示最多三条行动；材料、证据关联来自替入行动自身。候选池只用于顾问审核，不进入客户组件或 PDF。截图检查发现旧 PDF 模板会打印内部 ID，因此按全局规则第 4 条，仅对 v12 隐藏这行元数据；未改历史交付文案、冻结报告或证据。
