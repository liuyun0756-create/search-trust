# P1-09 建议结构与示例文案设计

**固定结构。** 对已有客户行动，按 finding ID 去重并核对证据引用。问题取已确认 finding，依据取对应快照字段或原文，“为什么重要”取规则的 `impact_path` 并保留条件语气。修法、目标页/资料字段、如何验证分别取 `steps`、`target`、`completion`。优先级沿用行动顺序，工作量按修法类型由规则标为小/中/大，缺依据显示“未评估”。置信度取所用依据的最低有效置信度。只有示例文案交由 LLM 组织，技术复核和未确认的资料更正只显示结构化建议。保留原有最多三项及隐藏逻辑。

**逐项证据校验。** 从该行动的已绑定证据生成允许引用的带类型槽位。LLM 只能从批准的句式与槽位组合中选取并排序。服务端按模板逐段解析且要求渲染结果完全吻合，拒绝额外文字、未知槽位、不可见字符和未经批准的 URL。提取每个数值及其单位、范围、时间、限定词与主体，例如“至少”随下限一起比较，不能改写为总数。实体用完整词边界匹配同一快照中的商家、目标城市、已确认服务与竞品名，仅允许证据显式记录的别名。比对做 Unicode NFC、空白折叠及按字段约定的大小写归一化。每个声明须匹配批准的谓词和同一条证据的主体、对象与限定条件。禁止从不同证据拼出新声明、推算数值或声称因果。通用白名单仅含句式里的介词、冠词、连接词及非承诺动作词，如 `the`、`and`、`for`、`contact`。服务、地区、数字、比较级和营销形容词均须独立校验。任一项失败时整条示例隐藏，结构化建议照常显示。

**引用站内原文。** 先复用 P1-03 的页面证明元素和 P1-08 的页面位置证据，按相同客户域名、确认证据主题及目标城市精确匹配。只有已成功采集的非归档页可见正文中存在可校验的原句、页面 URL 与冻结定位时，才将修法改为“引用已有内容”，逐字展示原句及来源。同页、截断片段、页脚套话与竞品内容都不可用。符合条件时直接引用，跳过 LLM。示例与引用都过合规词表。P1-10 完成前，按词边界和常见变形拦截疗效、胜诉、排名及其他结果承诺，例如 `cure`、`win your case`、`guaranteed ranking`、`guaranteed results`；引文触发时也隐藏相应文案。

**模型、版本与三端。** 拟用 `gpt-4.1-mini`，每份报告最多一次批量调用，最多三条例文。按规划假设 $0.80/百万输入 token、$3.20/百万输出 token，3,000 输入与 900 输出约 $0.0053/份，实施前核价。8 秒超时，无重试，降级为仅结构化建议，用户无需额外点数。拟 v20 / 报告 2.2.15 / 合约 2.2.20 / manifest v10。`V22_ACTION_EXAMPLE_COPY_ENABLED` 默认关闭，依赖 GBP、落地页、原因和本地实体四个现有开关及 v18 已绑定输入；无效组合告警并沿用当前规则集。P1-02 第二段保留 v19，P1-09 不开启评论采集。将已校验文案、证据引用和校验版本随报告冻结，重放读冻结结果。v1–v18 逐字节一致，v19 单独锁定兼容。客户网页、分享页和 PDF 使用同一净化投影，仅显示已通过的文案，屏蔽内部规则 ID、采样坐标、语言/设备与技术定位字段。顾问可见引用明细及拒绝原因。

**离线评估。** 用六站金标准和第六次冒烟客户的冻结输入离线生成 v18 投影。客户行动已引用、状态 `confirmed`、置信度中/高且引用完整的去重 finding 数分别为 All Star 2、Nova 4、PR 5、Seamless 9、Vision-Tech 4、Volcanoes 0、第六次冒烟客户 4，共 28 条，支撑 13 项行动。其中有 5 项标题/服务文案候选，引用站内原文后，进入 LLM 的数量可能更少。设计阶段调用 0 次。实施验收逐站记候选数、已引用、尝试生成、生成成功、被校验拦截及原因、发布数。人工逐条核对全部候选及全部输出，记录错误放行与误拦。留出确定性负例覆盖数字单位、他方商家、未确认服务、承诺、额外句子和引用错页，再核对三端展示及重放零调用。
