## 实现说明

1. 本阶段直接使用 `evidence_input.context.queries`，顺序写入 manifest v4 的 `keyword_queries`。不新增目标词字段、planning v2、系统建议、分页或来源类型。开关关闭时仍走现有 v12 输入；不升级已有运行中的冻结报告。
2. Organic 只检查保存的 Google Search 自然结果，按网站域名归属。请求成功、可解析、身份可判时，1 条、9 条也可形成有效负向检查；不要求 10/20 条。沿用既有相关性和本地化安全检查，外地样本仍未检查。Map Pack 只读 local_pack，使用 P1-05 D/P 门槛及所选分支 ID；同域名的其他分支不算命中。没有分支归属证据不猜。
3. observed 的位置和 rank_source 只读已保存记录；无 URL 但明确同分支 ID 的 Map Pack 仍可验证。缺段、失败、丢项、归属不明保留 not_checked，不把 Google Maps 填入 Map Pack。无分页，“前20”文案不进入新增客户模块。
4. 每渠道 K=observed+not_detected、H=observed、N=词数；K<2 未评估；3H≥2K strong，3H≥K medium，其余 weak。以整数比较避开 1/3、2/3 浮点边界；未知不计 0。客户只有分级和 K/N，不输出比例。
5. 模块的来源引用直接指向保存的 SERP，不依赖发现卡片最多20条证据的裁剪；不解析 observed_fact 文案取数。客户白名单不包含坐标、语言、设备、CID、内部规则/引用、rank_source、ratio。
6. 新增模块不生成 finding 或 action。六站 v14 的原有 findings/actions/evidence 与同输入 v13 相等。冻结证据与 truth.json 不改写。
7. 数据库只在本地 PGlite 执行完整迁移链与真实 RPC；生产未执行迁移。正式启用仍需负责人批准与第二段接入，本轮没有配置变更。

### 实现说明

1. 第2步先确认并免费保存商家/服务/市场，再在同一第2步呈现 `Target keywords (3–5)`。SEO可以逐词修改和上下移动，所有建议标 `Pending SEO confirmation` 并显示来源。勾选明确确认并成功保存后才出现收费启动页。旧未收费草稿提供显式新建入口，不在恢复时补词。
2. 首尾空白去掉；大小写重复（含 Straße/STRASSE）阻止确认，提示修正，不默默选择某个拼写。合法词保留大小写、内部拼写及 near me，不由后端加城市。词长按 Unicode 字符数≤300。编辑中的无效值可以暂存，正式确认必须3–5个有效、唯一的词。
3. 建议优先级为同范围的全部已保存SEO词（3或5个均保留）→已确认服务/市场模板→已匹配GBP类别及明确出现在title/H1的服务短语。GBP正向匹配要求域名或电话匹配，并在前端按选定公开档案链接筛选。title/H1不直接整段当服务：需有既有结构化服务短语在其中实际出现；Home/Privacy Policy/Terms of Use等通用词不作建议。没有源信息时不猜，也不重新获取页面。
4. `case_planning_settings` 继续 append-only。v2增加 target_keywords、keyword_scope 和 keyword_confirmation；确认人/时间由 SQL 写入，不能由浏览器伪造。原有 revision、所有权、RLS、Case行锁和精确次版本幂等复用；v1 不回填。
5. `prospect_target_keyword_bindings` 在同一个扣点事务中、扣点前验证来源 revision，冻结 `{queries, queries_digest, planning_revision}` 和服务/市场范围。绑定只追加不可更新。生成 intake、准备请求和生成输入再次校验，查询必须与 discovery 同一列表、同一顺序。其他 planning 新 revision 可保存，但不能把不同词带进同一 discovery。错误路径没有自动重采。
6. 新内部信封为 `v22_analysis_request_envelope_v2`，避免原地改变旧 v1 信封语义。v14/2.2.9/manifest v4 沿用第一段；新流程传 `confirmed_queries`，同时验证保存的采集 context.queries 完全一致。旧 v2 本地草稿、旧已付 reserved workflow、旧内部信封仍走原路径，即使后来开启开关也不升级成 v14。
7. 前后端均用 `V22_TARGET_KEYWORDS_ENABLED`，默认false；前端还要求现有dispatch/intake入口启用。关闭时不显示编辑区、不增加字段或请求头，不改变原模板词请求。已存 v3 遇功能关闭会显示可恢复提示，不默默降级为另一词表。启用前需两端版本和本迁移先就绪，本轮没有开启任何真实开关。
8. 加载、保存、响应丢失、revision冲突分别给可读提示和明确重试入口，保留编辑值。coverage真实disabled及按钮旁原因沿用712b7ba方式；保存词表与discovery不一致时明确提示开始新Case，不发分析请求或新发现请求。
