## 实现说明

### 字段及状态

| 提供商字段 | V2 字段 | 处理 |
|---|---|---|
| `type` / `types` | `categories` | 字符串或字符串数组；按返回顺序去重，不推断主类别。 |
| `rating` | `rating` | 0–5 的有限数值。 |
| `reviews` | `review_count` | 非负整数，拒绝布尔值、字符串和评论明细数组。 |
| `hours` | `hours` | 保留按星期组织的对象或对象列表，以及原营业时间文字。 |
| `operating_hours` | `operating_hours` | 单独保留相同结构；不覆盖或合并 `hours`，不补齐未返回的星期。 |
| `photos_count` / `photo_count` | `photo_count` | 返回明确的非负整数才记录；两个别名冲突时为 unsupported。不以 `images` 数组长度或照片链接推断总数。 |

未出现键为 `not_returned`；明确返回 null、空白文字、空列表或空对象为 `returned_empty`；无法安全解码、类型不符或超出边界为 `unsupported`。这些状态的标量值为 null、类别值为空数组，均不是 observed。只有明确返回的零值才记为 `observed / 0`。

类别最多 20 个、单项 240 字符；每个营业时间结构最多 7 个星期条目、每段文字最多 500 字符；计数上限 10 亿。超出结构边界只使对应新字段 unsupported，不丢弃身份已验证的整个资料。采集失败快照的新增字段也必须全为 `request_failed`；真实任务的提供商故障沿用原错误路径，不生成“缺少字段”结论。

新字段在本任务中只保存，不加入新发现、比较结论或行动建议；没有采集评论明细，也没有改变历史电话/地址规则。因此规则集、报告及 manifest 的结构版本不变，变化的是其引用的 **`customer_public_gbp_snapshot_v2`**。新采集阶段和检查点同时升至 V2；旧检查点仍读取 V1，保留原字段集合及 checksum，不补字段、不重新采集。

数据库迁移基于 `pg_get_functiondef` 修改现行函数中的版本条件，并在预期条件不存在时停止；不复制旧版本函数覆盖后续安全/扣费改动，不更新既有快照行。本地 PGlite 已执行全部迁移。以后部署需先安装迁移及兼容读取的前端，再切换产出 V2 的后端；本次未部署。

## 改动前后对比

对同一脱敏夹具，实际分别执行了 `git show b83c6168953239f7c911364cd5b4525959dd112e:app/jobs_v22/customer_public_gbp_stage.py` 中的旧 `_sanitize()`（仅提取该函数）和工作区的新函数，输出为：

```text
Before: retained new provider keys = []
After: retained new provider keys = ['hours', 'rating', 'reviews', 'type']
```

以脱敏响应夹具作为输入：

```json
{
  "type": ["Coffee shop", "Cafe", "Coffee store", "Tea store"],
  "rating": 4.5,
  "reviews": 1388,
  "hours": [{"wednesday": "6:30AM–5PM"}, {"thursday": "6:30AM–5PM"}, {"friday": "6:30AM–5PM"}]
}
```

改动前：`_sanitize()` 不保留这些键，V1 `record.fields` 仅有名称、网址、地址、电话、服务区域、是否为服务区域商家六项。

改动后：V2 在原六项之外记录：

```json
{
  "categories": {"state": "observed", "value": ["Coffee shop", "Cafe", "Coffee store", "Tea store"]},
  "rating": {"state": "observed", "value": 4.5},
  "review_count": {"state": "observed", "value": 1388},
  "hours": {"state": "observed", "value": [{"wednesday": "6:30AM–5PM"}, {"thursday": "6:30AM–5PM"}, {"friday": "6:30AM–5PM"}]},
  "operating_hours": {"state": "not_returned", "value": null},
  "photo_count": {"state": "not_returned", "value": null}
}
```

移除 `rating` / `reviews` 时对应值为 `not_returned / null`；明确返回 `reviews: 0` 时才是 `observed / 0`。旧 V1 冻结快照读取后仍只有原六项。客户报告的发现及行动类型不因这些新存储字段改变，也没有“缺少评分/照片”的结论。
