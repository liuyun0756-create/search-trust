# Owner metric review guidance

Pure `v22_metric_review_guidance_v1` derives an owner reading aid from already authenticated, validated, frozen ActionFacts. Its facts checksum identifies the precise input; it is not a report checksum, new evidence or authorization boundary. Python is the reference; TypeScript matches 16 exported directed cases. No database, collection, payment or source mutation is added.

Each metric retains its own gate: unselected source, waiting window, source restrictions, undefined CTR denominator, descriptive search values, limited session snapshot, or absent event values. Actual counts and fractions remain visible where valid. Event values are never inferred from sessions. Zero is not missing; zero baseline has no relative percentage. Inconsistent counts/deltas/ratios are rejected. Source-specific scopes, dates, restrictions and recorded implementation context are visible with concrete next checks.

`EvidenceFacts` integrates the aid in evidence preparation and decision review; detailed original source facts remain expandable. The owner report route shows the same aid for its frozen facts. Delivery edits, underlying report contracts, customer/PDF/share projections, generated decisions and stored version differences remain unchanged. No extra feature gate is needed: the existing owner-workspace/review-delivery gates still apply. No actual environment flag has been enabled.

This is not empirical calibration. `calibration_status` stays `not_calibrated`, `effect_conclusion` null and causal attribution false. There is no arbitrary low-volume threshold, confidence label or automated continue/adjust recommendation. See the 2026-10-28 empirical-calibration entry document for the still-required authorized-data and hold-out validation work.

Backend export: `.venv/bin/python scripts/export_v22_metric_review_guidance.py --frontend-dir ../search-trust --check`. The independent contract does not replace historical source/report schemas. Generate `types.ts` from its schema with the existing json2ts options when intentionally updating this rule version.
